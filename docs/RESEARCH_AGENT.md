# Программа-агент: как помогать проекту без ИИ-ассистента

[English](RESEARCH_AGENT.en.md) · [中文](../i18n/zh/RESEARCH_AGENT.md) · [Español](../i18n/es/RESEARCH_AGENT.md) · [Français](../i18n/fr/RESEARCH_AGENT.md) · [Deutsch](../i18n/de/RESEARCH_AGENT.md) · [Italiano](../i18n/it/RESEARCH_AGENT.md) · **Русский** · [Português](../i18n/pt/RESEARCH_AGENT.md) · [العربية](../i18n/ar/RESEARCH_AGENT.md)

Состояние на 22 ноября 2026 года. Версия агента 0.1.0. Инструкция для участника:
[agent/README.md](../agent/README.md) ([по-русски](../i18n/ru/AGENT.md)).

## Зачем

Репозиторий рассчитан на людей, у которых есть ИИ-ассистент: он читает документы и помогает
проектировать. У большинства людей такого ассистента нет, но есть компьютер или телефон.
Программа-агент даёт им способ участвовать: она периодически заглядывает в этот репозиторий,
берёт задания, выполняет их на устройстве участника и публикует результаты.

На этом этапе **вознаграждений нет**: ни кредитов, ни денег, ни обещаний будущих начислений.
Цель — привлечь к проектированию архитектуры как можно больше вычислительных ресурсов
и независимых проверяющих.

Агент — **инструмент исследования, а не сеть SkyNet**. Он устроен проще и централизованнее,
чем должна быть сеть, и сам её обязательным требованиям не удовлетворяет. Ниже это сказано
прямо в каждом месте.

## Как это устроено

| Часть | Где лежит | Что делает |
|---|---|---|
| Список заданий | `tasks/index.json` и подпись `tasks/index.json.sig` | Называет встроенное вычисление, его параметры и число независимых порций |
| Агент | `agent/skynet_agent/`, только стандартная библиотека Python 3.9+ | Проверяет подписи, выбирает порцию, считает, публикует, обновляется |
| Описание версии | `agent/release.json` и подпись | Перечисляет файлы агента с размером и SHA-256 |
| Запускатель | `agent/launcher.py` | Запускает текущую версию, переходит на новую, откатывается со сломанной |
| Результаты | Комментарии в задаче GitHub от имени участника | Машиночитаемая запись с отпечатком результата |
| Сводка | `results/`, строит `tools/collect_results.py` | Сверяет результаты разных людей, перепроверяет находки |

Один цикл работы агента:

1. Раз в 30 минут (с разбросом) скачивает описание версии и список заданий.
2. Проверяет подпись каждого из них ключом выпуска, зашитым в установленную копию.
3. Если есть версия с большим номером, скачивает её файлы, сверяет каждый с отпечатком,
   ставит рядом с текущей и перезапускается.
4. Выбирает случайную порцию задания, которую ещё не считал.
5. Считает её в отдельном процессе с низшим приоритетом и ограничением по времени.
6. Кладёт результат в «исходящие» и публикует комментарием в задаче GitHub. Результаты одного
   задания публикуются пачкой, не чаще одного комментария в час, чтобы не заваливать задачу
   и подписчиков уведомлениями. После неудачной попытки следующая откладывается: на минуту,
   затем вдвое дольше, но не больше часа. Если опубликовать нельзя (нет входа в GitHub), агент
   после трёхсот неопубликованных результатов перестаёт брать работу и сообщает об этом.

Планировщика нет: каждый агент выбирает порцию сам. Совпадение порций у разных участников
задумано: все вычислительные задания целочисленные, поэтому на любом устройстве получаются
одни и те же цифры, и порция считается подтверждённой, когда одинаковый отпечаток
опубликовали столько разных учётных записей, сколько требует задание.

## Задание — это данные, а не программа

Агент никогда не скачивает и не запускает код из задания. Задание называет одно из
вычислений, встроенных в агент («ядро»), и передаёт ему числа. Каждое ядро проверяет
параметры и ограничивает объём работы. Новый вид вычислений появляется только с новой
подписанной версией агента, исходный текст которой лежит в репозитории и читается глазами.

Ядра версии 0.1:

| Ядро | Что считает |
|---|---|
| `selftest` | Контрольный целочисленный расчёт: отпечаток обязан совпасть на всех устройствах |
| `exit-scam-a` | Точное ожидание выплаты участника, который перед уходом сдаёт подделки (вариант А из [CURRENT_DESIGN](CURRENT_DESIGN.md)); перебирает семейство стратегий и сообщает те, что выгоднее честного ухода |
| `lottery-b` | Точная вероятность убыточного месяца или квартала, если платить только за проверенные задания (вариант Б) |
| `ai-answer` | По желанию участника: вопрос для локальной ИИ-модели, которую он запускает сам |

Точная модель каждого расчёта записана в начале исходного файла ядра, чтобы любой мог
пересчитать результат независимо. Задания и их смысл: [tasks/README.md](../tasks/README.md).

**Граница с правилом проекта об опытах.** Первые задания — это расчёты по формулам
из документов (анализ стоимости и поиск контрпримеров) и вопросы к языковым моделям.
Это не измерения на оборудовании и не опыты с сетью. Измерительные задания (например,
совпадают ли биты целочисленного вывода на разных видеокартах) публикуются только после
решения владельца проекта открыть опыты.

## Режим ИИ (по желанию, опытный)

Участник, который запускает у себя открытую модель (Ollama, сервер llama.cpp, LM Studio
и подобное с интерфейсом, совместимым с OpenAI), может включить `ai.enabled`. Тогда агент
передаёт модели вопросы из подписанного списка и публикует ответы. Так люди без подписки
на ИИ, но с видеокартой становятся участниками «совета моделей».

- Агент не скачивает и не запускает модель и по умолчанию обращается только к серверу
  на том же компьютере.
- Вопрос и документы, которые он цитирует, заданы подписанным списком. Каждый документ
  сверяется с отпечатком, поэтому подсунуть модели другой текст нельзя.
- Ответ по умолчанию ждёт в «исходящих», пока участник его не одобрит: текст публикуется
  от его имени.
- Ответ помечается как машинный и никем не проверенный. Число ответов на вопрос ограничено.

Проверено только на подставном сервере в автоматических тестах. С настоящими средами
запуска моделей режим ещё не проверялся.

## Приложение для Android (опытное)

Для тех, кто не хочет настраивать Termux, есть приложение: один файл APK, кнопка «Start».
Исходный код и инструкция: [android/README.md](../android/README.md). В приложение встроен тот же
пакет `skynet_agent` и Python (через Chaquopy). Отличия от агента на компьютере:

- Android не даёт запускать отдельные процессы Python, поэтому порция считается в фоновом
  процессе самого приложения, по одной. Если порция идёт дольше предела, сторож завершает этот
  процесс, Android запускает службу снова, а задание остаётся более быстрым устройствам.
- Новая версия агента берётся из репозитория с той же подписью ключа выпуска. Проверяет её
  встроенная копия; если новая версия здесь не запускается или её файлы изменены, приложение
  возвращается к встроенной.
- Само приложение (экран, служба, сторож) меняется только новым APK. APK подписан отдельным
  ключом ведущих проекта: это вторая единая точка доверия, которой в сети быть не должно.
- Результаты публикуются с токеном GitHub, который участник вставляет в приложение.
- Работает только на зарядке, если участник не разрешил иное. Режима ИИ нет.

Состояние на 22 ноября 2026 года: приложение собирается, его часть на Python проходит тесты на
компьютере (`agent/tests/test_android_glue.py`). Проверочная сборка с тестовым ключом прошла
на эмуляторе Android 14 (x86_64) с локальным тестовым репозиторием: установка, проверка подписей,
расчёт всех 7 тестовых порций без ошибок, ожидание без зарядки, работа в фоне, сохранение токена
и обращение с ним к настоящему GitHub API, остановка и повторный запуск с сохранённым состоянием.
На настоящем телефоне приложение ещё не запускалось, сборка для ARM (`arm64-v8a`) не проверялась. Через Google Play оно не распространяется: его правила запрещают приложения,
загружающие исполняемый код.

## Чему доверяет агент

| Что | Доверие |
|---|---|
| Подпись Ed25519 ключом выпуска | Да. Без неё не принимается ни версия, ни список заданий |
| Канал (HTTPS, зеркало, сам GitHub) | Нет для целостности: подмена файла ломает подпись или отпечаток |
| Содержание задания | Нет: параметры проверяются, объём работы ограничен, кода в задании нет |
| Ответ локальной модели | Нет: это текст, он публикуется как непроверенный |
| Первая установка | Да, каналу HTTPS до GitHub. Проверить установленное можно командой `selftest --online` |

**Честная граница.** Держатель ключа выпуска может доставить программу на все установленные
агенты. Сейчас ключ у ведущих проекта. Это единая точка доверия, которой в сети SkyNet быть
не должно: в целевом проекте программа обновляется только на версию, отпечаток которой
принят голосованием участников в общем журнале, а подписи чьим-то ключом недостаточно
([CURRENT_DESIGN, раздел 8](CURRENT_DESIGN.md)). Участник, который не хочет доверять ключу,
ставит `update` в `notify` и обновляется вручную, прочитав изменения.

## Таблица угроз

| Угроза | Чем закрыта | Что остаётся |
|---|---|---|
| Взлом репозитория или учётной записи с правом записи: подмена агента | Версия принимается только с подписью ключа, которого в репозитории нет | Закрыто, пока ключ не украден |
| Подмена файла по дороге или на зеркале | Подпись описания версии и SHA-256 каждого файла | Закрыто |
| Откат на старую уязвимую версию | Номер версии должен быть больше текущего | Закрыто для установленных агентов. Новая установка берёт то, что лежит в репозитории |
| Вредное задание | Задание не несёт кода; ядро проверяет параметры и ограничивает объём работы и памяти; есть предел времени | Ограничено: подписанное задание может занять процессор до предела времени |
| Повтор старого подписанного списка заданий | Номер списка должен быть не меньше уже виденного; у списка может быть срок годности | Ограничено: свежая установка может получить старый список и зря посчитать закрытые задания |
| Сломанная версия | Запускатель возвращает прежнюю версию после трёх быстрых падений или если файлы новой версии пропали, и запоминает негодный номер. Повторные просьбы о перезапуске он выполняет с растущей паузой | Закрыто для падений при запуске. Тихую ошибку в расчёте ловит сверка результатов |
| Кража ключа выпуска | Ключ лежит вне репозитория, на Windows зашифрован для учётной записи владельца | **Открыто.** Вор может выпустить вредную версию. Смена ключа делается новой версией, подписанной старым ключом, и вору она доступна тоже |
| Потеря ключа выпуска | Резервная копия у владельца | Без ключа установленные агенты нельзя обновить: участникам придётся ставить агент заново |
| Подделка результата | Целочисленный расчёт сверяется между разными учётными записями; находки пересчитываются при сборе | Ограничено: один человек с двумя учётными записями «подтвердит» сам себя. Вознаграждений нет, поэтому выгоды в этом нет, но вредитель возможен. Ведущие выборочно пересчитывают |
| Поток мусорных комментариев от чужих учётных записей | Сборщик принимает только записи с верным отпечатком и известным заданием | Ограничено средствами GitHub |
| Утечка токена GitHub | Агент не хранит токен, берёт его у `gh` или из переменной и не отправляет никуда, кроме GitHub по HTTPS, без переадресаций | Токен с правом записи в публичные репозитории остаётся ответственностью участника |
| Чужой код рядом с агентом (подложенный модуль в текущей папке) | Изолированный режим Python (`-I`) | Закрыто. От программы с правами того же пользователя на том же компьютере защиты нет |
| Расход ресурсов участника | Один процесс по умолчанию, низший приоритет, пауза на батарее, предел времени, команды `pause` и `stop` | Электричество участник тратит сам и безвозмездно |
| Остановка всех агентов ведущими | Подписанная пометка `halt` в описании версии; действует и при выключенных обновлениях | Это намеренный рычаг: только остановка, без запуска чего-либо |

## Что агент сообщает о себе

Только содержимое опубликованной записи: имя задания, номер порции, числа результата,
время расчёта и, если не отключено, грубую метку платформы вида `linux-amd64-py3.12`.
Запросы идут только к GitHub. Сведения о файлах, сети и оборудовании участника не собираются.

## Порядок для ведущих

Ключ выпуска создаётся один раз и хранится вне репозитория:

```
python tools/keytool.py generate
```

Резервную копию секрета владелец делает сам, вручную, командой `python tools/keytool.py backup`,
и хранит её вне компьютера. Секрет нельзя показывать ассистентам, вставлять в чаты и файлы.

Новая версия агента:

```
python tools/make_release.py --seq <следующий номер> --version <x.y.z>
```

затем загрузка изменённых файлов `agent/` в репозиторий. Новый список заданий:

```
python tools/sign_tasks.py
```

затем загрузка `tasks/index.json` и `tasks/index.json.sig`. Сбор результатов:

```
python tools/collect_results.py
```

Остановить работу всех агентов до исправления ошибки: выпустить описание версии с
`--halt-through <номер>` и причиной.

## Чего здесь нет и почему это честно сказать

- **Это не распределённая сеть.** Задания и версии раздаёт один репозиторий, подписывает один
  ключ, результаты принимает одна площадка. Требования R1–R4 из
  [обязательных требований](../i18n/ru/REQUIREMENTS.md) к агенту не применяются и им не выполняются.
- **Нужна учётная запись GitHub.** Без неё результаты публикуются только вручную по ссылке.
- **Нет защиты от множества учётных записей.** Для безвозмездного этапа это приемлемо.
- **Android не проверен на настоящем устройстве**; автозапуск на macOS, Linux и Android
  проверен только на уровне создаваемых файлов. Два случая учтены по документации и тоже
  не проверены на настоящих устройствах: Python из Microsoft Store на Windows (он видит
  собственную копию `AppData` и реестра, поэтому папка агента лежит в профиле, а автозапуск
  добавляется вручную) и Python с сайта python.org на macOS без установленных сертификатов
  (агент повторяет запрос с системным файлом сертификатов).
- **Первые задания лёгкие.** Вся первая партия (702 порции) заняла на одном настольном
  компьютере 15,5 часа процессорного времени при 16 одновременных процессах с низшим
  приоритетом, то есть около часа по часам [измерено на одном ПК, 22 ноября 2026 года].
  Механизм готов принять тяжёлые задания. Что получилось: [results/FIRST_RUN.md](../results/FIRST_RUN.md).

## Что дальше

1. Измерительные задания на разных устройствах: главная неизвестная проекта — совпадение
   результата до бита на разных видеокартах. Это опыты, они ждут решения владельца.
2. Отказ от учётной записи GitHub: приём результатов через несколько независимых публичных
   площадок, как в целевом проекте сети.
3. Отказ от единого ключа: несколько независимых подписей, затем принятие версий по правилам
   самой сети.
4. Управление локальной моделью: скачивание открытой модели с проверкой отпечатка, чтобы
   режим ИИ включался одной командой.
