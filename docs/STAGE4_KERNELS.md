## Общие правила версии 1

В подписываемом задании имя ядра и целое `kernel_version: 1` хранятся раздельно. Вход `params` — объект со всеми перечисленными для ядра полями. Лишние и пропущенные поля, повтор ключа JSON, значения вне диапазона и неверные типы приводят к ошибке. Целое записывается целым литералом JSON, без десятичной точки и экспоненты. Строки и логические значения вместо чисел запрещены. Границы включительны. Оси сетки сохраняют входной порядок. Число units точно равно указанному для ядра размеру сетки, от 1 до 1 000 000. Номер unit начинается с нуля. В декартовом произведении последняя ось меняется быстрее всех.

Для сверки берут весь объект результата. В Python канонические байты равны `json.dumps(result, sort_keys=True, ensure_ascii=True, separators=(',', ':')).encode('ascii')`, без завершающего перевода строки. Хеш результата — SHA-256 этих байтов, 64 строчные шестнадцатеричные цифры. Порядок элементов массивов значим. Дробь в строке записывается в десятичной системе как `p/q` с положительным знаменателем после сокращения, включая `0/1` и целые с `/1`. Нет ведущих плюсов или нулей. Для М14 отдельно определён хеш байтов *внутри* результата упаковки. [Канонический кодировщик агента](../agent-go/canon/canon.go)

## М8. Масштаб T4 при одном обновлении от каждого участника

`t4-scale@1` вычисляет минимальное целое число токенов собственного обучения за раунд, при котором экзамен добавляет не более 20% вычислений. Для заданного бюджета токенов ядро также находит предельное число подающих. В модели каждый узел проверяет все `K=N` обновлений. База стоит один прямой проход на позицию, каждое обновление верхних слоёв — долю `a=L_a/L` прохода, а обучение одного токена стоит три прохода. Эти отношения заданы предложением. claude1, §5.4 «Цена» и §7.5, п. 4 · critic_claude, §1.8 и §10.4, п. 3 · [VERIFICATION_SEARCH, §5.3, М8](VERIFICATION_SEARCH.md)

| Поле `params` | Допустимые значения |
|---|---|
| `N` | Ось целых от 1 до 1 000 000. Число подающих в раунде |
| `n` | Ось целых от 1 до 1 000 000. Число экзаменных позиций |
| `a` | Ось пар целых `[p,q]`, где `1 ≤ p ≤ q ≤ 1 000 000`. Доля прохода на обновление |
| `D_budget` | Ось целых от 1 до 1 000 000 000 000. Бюджет токенов обучения на узел за раунд |
| `epsilon_bits` | Одно целое от 1 до 256. Задаёт `ε=1/2^epsilon_bits` для фиксированного экзамена. При заданном `n` стоимость одинакова для всех `ε` |

Все пять полей обязательны. Каждая ось — массив длины 1…32, значения уникальны с учётом сокращения дробей, порядок входного массива сохраняется. Число units равно произведению длин осей и не превышает 1 000 000. Нумерация с нуля по декартову произведению `N, n, a, D_budget` в порядке вложенных циклов, быстрее всего меняется бюджет. Одна unit выдаёт один объект.

Для выбранной точки положим `D=D_budget`, а `a=p/q` сократим. Измерим вычисления в единицах `1/q` прямого прохода на позицию. Тогда экзамен требует `E=n(q+Np)`, обучение требует `W=3Dq`, доля накладных расходов равна `E/W`. Деление на объём собственного обучения следует из формулировки «надбавка» в §5.4. Условие 20% эквивалентно `5E ≤ W`.

| Поле результата | Значение |
|---|---|
| `kernel` | Строка `t4-scale@1` |
| `N`, `n`, `D_budget` | Целые входной точки |
| `a`, `epsilon` | Сокращённые строки `p/q`; `epsilon` записывается как `1/q`, где `q = 2^epsilon_bits` — десятичное целое (например, `"1/4"` при `epsilon_bits = 2`) |
| `D_min` | Целое `(5E + 3q − 1) // (3q)`, где `//` — целочисленное деление вниз. Это округление порога вверх до целого токена |
| `fits` | Логическое значение `D_budget ≥ D_min`. Равенство засчитывается |
| `N_max` | `null`, если `W < 5nq` и даже базовый проход превышает бюджет. Иначе целое `(W − 5nq) // (5np)`. Ноль означает, что помещается только база. Предел может выходить за входную ось `N` |
| `overhead` | `E/W` в виде сокращённой строки `numerator/denominator` |

Обратная граница следует из линейного неравенства `5npN ≤ W − 5nq` при положительном `p`. При разрешённых параметрах `5E+3q−1 ≤ 5 000 005 000 002 999 999`, `W ≤ 3·10^18`. Знаменатели положительны. Достаточно знаковых 64-битных целых и сокращения дроби через НОД. В Go для `overhead` используется `big.Rat`, для `2^epsilon_bits` — `big.Int`. На одну unit приходится разбор не более 128 элементов осей и постоянное число арифметических операций.

Для `n=3, N=4, a=1/2` экзамен стоит 9 проходов, при 15 токенах обучения он занимает ровно пятую часть. При 14 токенах предел снижается до трёх подающих. При `epsilon_bits=2` получаются следующие канонические байты.

```json
{"D_budget":15,"D_min":15,"N":4,"N_max":4,"a":"1/2","epsilon":"1/4","fits":true,"kernel":"t4-scale@1","n":3,"overhead":"1/5"}
```

Для ориентира §5.4 при `n=100000, N=10000, a=4/36` точный минимум равен 185 351 852 токенам. Физическая цена зависит от повторного использования префиксов, объёма кэша, выходной головы, нормировки, трафика и фактической цены обучения верхних слоёв. Формула охватывает только описанный в §5.4 счёт проходов. Для оценки статистического порога при изменении `ε` служит М10. Предложенное задание задаёт `ε=2^-80` согласно численному ориентиру D19. critic_gpt, раздел о claude1, «Скрытая цена T4» · [ROADMAP, D18–D19](ROADMAP.md)

## М10. Порог экзамена T4 — `exam-thresholds@1`

М10 определяет, насколько большим должно быть среднее наблюдаемое улучшение на экзамене, чтобы оно превысило статистический порог. Для одного заранее зафиксированного кандидата берутся `n` независимых позиций с возвращением. Разность потерь на каждой позиции обрезается до `[−B/2, B/2]`. Входная `V` — выборочная дисперсия обрезанных разностей с делителем `n−1` (квадрат стандартного отклонения). Границы в натах на позицию берутся из шага 6 описания T4. claude1, §5.4 · критик Claude, §1.8

| Метод | Точный порог `t` |
|---|---|
| Хёфдинг | `B·√(ln(1/ε)/(2n))` |
| Эмпирический Бернштейн | `√(2V·ln(2/ε)/n) + 7B·ln(2/ε)/(3(n−1))` |

**Параметры и units.** Обязательны пять полей. Поля `n`, `epsilon_bits`, `B`, `variance` — оси длиной от 1 до 32, каждая в порядке входного массива. Значения на оси различны, дроби сравниваются после сокращения.

| Поле | Допустимые значения |
|---|---|
| `n` | Число позиций, целое от 2 до 1 000 000 |
| `epsilon_bits` | Целое `k` от 1 до 128, `ε = 2⁻ᵏ` на одно сравнение |
| `B` | Ширина диапазона обрезки, целое от 1 до 64 |
| `variance` | Дробь `[p,q]`, целые `0 ≤ p ≤ 10⁶` и `1 ≤ q ≤ 10⁶`. Во всех точках сетки `V=p/q ≤ B²·floor(n/2)·ceil(n/2)/(n(n−1))` |
| `digits` | Одно целое `d` от 1 до 9. Гарантированная абсолютная ширина каждого интервала меньше `10⁻ᵈ` |

Максимум дисперсии достигается на концах диапазона, поскольку дисперсия выпукла по каждому наблюдению. При `j` значениях на одном конце её числитель пропорционален `j(n−j)`, что даёт указанную границу. Число units равно произведению длин четырёх осей и не превышает 1 000 000. Нумерация совпадает с `itertools.product(n, epsilon_bits, B, variance)`, начиная с нуля.

**Алгоритм побайтного воспроизведения.** Для обоих методов записать `t = √(A·ln 2) + C·ln 2`. У Хёфдинга `A=B²k/(2n), C=0`. У Бернштейна `A=2V(k+1)/n, C=7B(k+1)/(3(n−1))`. Все деления здесь рациональные.

1. Взять `S=10^(d+1)`, `l=693147180559945309/10¹⁸`, `h=693147180559945310/10¹⁸`.
2. Нижняя граница равна `(floor(√(S²Al)) + floor(SCl))/S`. Верхняя равна `(ceil(√(S²Ah)) + ceil(SCh))/S`. Оба слагаемых округляются **по отдельности**.
3. Для неотрицательной дроби `x=p/q` вычислить `r=isqrt(p//q)`. Это `floor(√x)`. Для верхней границы прибавить к `r` единицу ровно при `r²q < p`. Обычные `floor` и `ceil` также выполняются целочисленным делением. Все полученные дроби сокращаются.

**Сертификат точности.** Из ряда для `2·atanh(1/3)=ln 2` берём `T=2·Σ 1/(j·3ʲ)` по нечётным `j=1,3,…,39`. Хвост положителен и ограничен первым пропущенным членом, умноженным на `1/(1−1/9)`. Целочисленным сравнением получаем `l < T < ln 2 ≤ T + 9/(4·41·3⁴¹) < h`. Монотонность обоих слагаемых и направленное округление обеспечивают включение истинного порога. В заданном диапазоне `A ≤ 264192` и `C ≤ 19264`. Поскольку `√h+√l > 1`, замена `l` на `h` меняет неокруглённый порог меньше чем на `(515+19264)·10⁻¹⁸`. Округление расширяет интервал меньше чем на `4/S`. Сумма меньше `10⁻ᵈ` даже при `d=9`. На unit достаточно четырёх целых квадратных корней и постоянного числа операций над целыми и дробями размером в несколько сотен бит, независимо от `n`.

**Ответ.** Поля `n`, `epsilon_bits`, `B` и `digits` — целые координаты и точность. `variance` — строка с сокращённой дробью. `hoeffding` и `bernstein` — массивы из двух таких строк, нижняя граница первой. Для `n=2, k=1, B=2, V=0, d=1` ядро выдаёт следующие канонические байты.

```json
{"B":2,"bernstein":["323/50","647/100"],"digits":1,"epsilon_bits":1,"hoeffding":["83/100","21/25"],"kernel":"exam-thresholds@1","n":2,"variance":"0/1"}
```

Для заданного предельного порога `τ` минимальный размер экзамена **на сетке** установлен, когда в выбранной точке верхняя граница `≤ τ`, а у всех меньших `n` при тех же параметрах нижняя граница `> τ`. Если интервал пересекает цель, может потребоваться большая точность. Числа характеризуют одностороннее сравнение усечённого среднего при фиксации до внешнего маяка. Поправка за выбор среди нескольких кандидатов, качество вне экзамена, выбор `τ` и величина реального эффекта требуют отдельных данных или правил. Выплата за улучшение остаётся исследовательским вариантом по D18. [ROADMAP, D18–D20](ROADMAP.md) · критик GPT, оценка T4

## М12. Как меняется начисление владельца дублей при слиянии суммой

В работе для М12 указаны линейно-квадратичные потери с известными градиентом и гессианом, три правила атрибуции, точные дубли и дубли с шумом. Выбираем явно разобранный в §5.4 вариант `merge = sum`. Критик приводит случай, когда даже повторное добавление одного и того же шага улучшает функцию потерь. Ядро `merge-attribution@1` проверяет это на явных входных коэффициентах. claude1, §5.4, шаги 6–7 и п. 2 «Атрибуция и дубли», §7.5, п. 7 · critic_gpt, таблица о claude1, строка T4

| Поле `params` | Смысл и включительные границы |
|---|---|
| `scale` | Общий знаменатель `s`, целое 1…10 000 |
| `g` | Вектор числителей градиента в базовой точке. Его длина задаёт размерность `d`, 1…8 |
| `hessian` | Симметричная матрица числителей гессиана, массив из `d` строк по `d` компонент |
| `updates` | Массив из `b=1…8` исходных векторов числителей длины `d`, в порядке подачи. Одинаковые векторы разрешены |
| `owner` | Целый индекс исходной заявки проверяемого участника, от 0 до `b−1`. Другие исходные заявки принадлежат другим участникам |
| `copies` | Ось из 1…8 различных целых 1…8. Выбранное `c` задаёт число добавленных заявок того же участника |
| `noise` | Ось из 1…32 попарно различных векторов числителей длины `d`. Нулевой вектор даёт точный дубль |
| `threshold` | Целый числитель 0…10 000 для вычета `t=threshold/s` из оценки каждой заявки |

Каждая компонента `g`, `hessian`, `updates` и `noise` — целое от −10 000 до 10 000. Для получения математического значения каждой компоненты разделить её на `s` **один раз**, в том числе для матрицы. Версия поддерживает рациональные коэффициенты с общим знаменателем в указанном диапазоне. Симметрия обязательна, знак кривизны произволен. Входные оси `copies, noise` образуют сетку. Для unit `u` взять индексы `divmod(u,len(noise))` соответственно. После исходных `b` заявок добавить `c` векторов, каждый равен `updates[owner] + noise[j]` в числителях. Исходные векторы сохраняются. Наборы заявок до и после добавления рассматриваются по отдельности.

**Расчёт.** Пусть `U` — множество индексов заявок одного набора, а `x(S)` — сумма их **математических** векторов обновлений по подмножеству `S`. Выигрыш по потерям задан как снижение относительно общей базы,

```text
v(S) = −gᵀx(S) − x(S)ᵀ H x(S)/2,     v(∅) = 0.
```

Для каждого индекса `i` вычислить три **знаковые** оценки. `separate[i]=v({i})`. Правило исключения одного, `loo[i]=v(U)−v(U без i)`. Оценка `shapley[i]` равна среднему приросту `v(S∪{i})−v(S)` по всем перестановкам индексов, где `S` состоит из предшественников `i`. Это правило применяется к полной функции снижения потерь. Для вычисления без факториального перебора положим `q_i=v({i})`, `h_ij=−x_iᵀ H x_j`. Симметрия даёт `v(S)=Σ q_i + Σ_{i<j} h_ij` по участникам `S`. При исключении участника исчезают все его парные члены. В равномерной перестановке каждый другой участник предшествует ему ровно в половине случаев. Поэтому

```text
loo[i]     = q_i + Σ_{j≠i} h_ij
shapley[i] = q_i + (Σ_{j≠i} h_ij)/2
v(U)       = Σ shapley[i].
```

Далее отдельно для каждого правила оценку `z` переводят в начисление `max(0,z−t)` в единицах улучшения (коэффициент оплаты κ принят за единицу). Сначала начисляют по каждой заявке, затем складывают начисления владельца. `gain` — начисление владельцу за его исходную и все добавленные заявки после добавления минус начисление за его одну заявку до добавления. Положительный знак означает выигрыш от дополнительных подач в этом примере.

**Формат ответа.** Ключи `kernel` (строка `merge-attribution@1`), `owner`, `scale`, `copies` (выбранное целое из оси), `noise` (выбранный вектор целых числителей), `baseline`, `with_copies` и `gain`. Каждый из объектов `baseline` и `with_copies` содержит `value` — дробь `v(U)` — и поля `separate`, `loo`, `shapley` — массивы дробей в порядке индексов заявок. Объект `gain` содержит по одной дроби под каждым из трёх имён правил. Все выходные дроби — канонические строки.

**Арифметика и пределы.** Общий знаменатель промежуточных оценок — `2s³`. Если `G, A, z_i` — входные целые числители градиента, гессиана и шага, числитель `q_i` равен `−2s Gᵀz_i−z_iᵀAz_i`. Половине парного члена соответствует целый числитель `−z_iᵀAz_j`. Числитель вычета равен `2s²·threshold`. После добавления до 16 заявок и `|z_ij| ≤ 20 000`. Отсюда `|z_iᵀAz_j| ≤ 8²·20 000²·10 000 = 2,56·10¹⁴`, линейная часть по модулю не более `3,2·10¹³`. Даже сумма 16 полных оценок LOO и вычетов по модулю меньше `1,3·10¹⁷`. Все умножения и частичные суммы помещаются в знаковые 64 бита. Реализация сокращает дроби через `big.Rat`. Время `O(k d²+k²d)` при `k ≤ 16`, без таблицы подмножеств. Память ограничена входными векторами, матрицей, тремя оценками на заявку и результатом.

**Ручная проверка.** При `v(x)=3x−x²/2`, одной заявке `x=1` и нулевом пороге исходная оценка равна `5/2` по всем правилам. После точного дубля `v(2)=4`. Правила дают за каждую заявку `5/2` по отдельности, `3/2` при исключении и `2/1` по Шепли. Суммарный выигрыш владельца равен соответственно `5/2`, `1/2`, `3/2`. Одного этого примера достаточно, чтобы опровергнуть отсутствие выигрыша для каждого из трёх правил на всём семействе таких моделей при нулевом пороге.

**Область вывода.** Набор участников сравнения фиксирован. Шум задаётся явным вектором, порог задаётся входом. Приёмка, повторный отбор состава после вычета порога, затраты подачи, обучение параметров, внешние эффекты и эмпирический экзамен находятся вне этой модели. Численный выигрыш относится к сумме начислений по выбранному правилу. Полная проверка D1 требует сравнить полезности коалиции также с честной работой и с бездействием. [THREAT_MODEL, §§1.4–1.5](THREAT_MODEL.md) · [ROADMAP, D18 и D25](ROADMAP.md)

## М14. Проверка формул конечным перебором

Ядро `verification-enumerations@1` повторяет три малых опыта. Оно позволяет проверить, сохраняет ли упаковка различие между разрешёнными векторами, и сколько ошибок пропускают два вида выборочной проверки. Исходные данные, порядок перебора и эталонные хеши опубликованы в GPT2, §6.2 и «Контрольный код для первого повтора». Цепочка задана в таблице «Что отдать мини-агентам», условие пропуска в поле — в §6.1. Работа GPT2 · [Сводка, §5.3](VERIFICATION_SEARCH.md)

Единственный параметр `cases` — массив из 1–4 различных строк из таблицы ниже. `units = len(cases)`. Нулевая нумерация, unit `u` вычисляет весь опыт `cases[u]`. Ключ `case` результата содержит эту же строку, `kernel` равен `"verification-enumerations@1"`. Формат остальных полей зависит от опыта.

| `case` | Поля результата помимо `case` и `kernel` | Контрольные значения |
|---|---|---|
| `packing-8` | Целые `total`, `true_accepts`, `false_accepts`, строка `verdict_sha256` | 441, 9, 0, `a5c8a8d715fb5293a4dd12753d3483e848f63cb24891a3e584bfdc81954f377c` |
| `packing-4` | Те же поля | 441, 9, 20, `fca92fea5a3148177517b737591e499ed021432078bd9803578a2eaad4074fc9` |
| `chain-8-2` | Целые `total`, `caught`, `missed` | 224, 56, 168 |
| `field-5` | Целые `total`, `caught`, `missed` | 25, 20, 5 |

**Разрядная упаковка.** Взять основание `B` из метки опыта. Перебрать `(x,y,c,d)` лексикографически по возрастанию, причём `x,y ∈ {−1,0,1}`, `c,d ∈ {−3,…,3}`. Внутренний цикл меняет `d`. Истинный результат `(s,t)=(2x−y,−x−y)`. Критерий приёмки — делимость `(c−s)+B(d−t)` на `B²` над целыми. При совпадении `(c,d)=(s,t)` приёмка увеличивает `true_accepts`, в остальных случаях приёмки — `false_accepts`. Записать в порядке перебора ровно 441 байт, каждый со значением 1 при приёмке и 0 при отказе. `verdict_sha256` — SHA-256 от этих сырых байтов в виде 64 строчных шестнадцатеричных цифр. Обычный хеш результата unit вычисляется отдельно от всего канонического JSON. Для ручной проверки при `B=4`, `x=−1`, `y=1` истинный ответ `(−3,0)` и заявка `(1,−1)` дают разность 0.

**Цепочка.** Для каждого единственного дефекта `h=0,…,7` перебрать все неупорядоченные пары без возвращения как `0 ≤ i < j < 8`. Увеличить `total` на 1 за каждую тройку, `caught` — если `h=i` или `h=j`. Число пропусков равно `missed=total−caught`. Для каждого `h` имеется 28 пар, из них ровно 7 содержат `h`.

**Поле.** Перебрать векторы `(x,y)∈{0,…,4}²`, включая нулевой. Ошибка `(1,−1)` пропущена ровно при `(x−y) mod 5 = 0`. `total` считает все векторы, `missed` считает пропуски, `caught=total−missed`. Пять диагональных пар дают пять пропусков.

Самая длинная unit проверяет 441 комбинацию, хранит 441 байт вердиктов для одного SHA-256. Счётчики не превышают 441, модуль выражения упаковки не превышает 46, наибольший модуль деления равен 64. Достаточно знаковых 32-битных целых. Результаты относятся к указанным диапазонам, одной фиксированной ошибке и полному перечислению равновероятных вариантов. Обобщение на реальный протокол потребовало бы обосновать распределение вызовов и независимость проверок.
