# Опыт D5: целочисленный Qwen3.5-4B

Состояние на 24 ноября 2026 года: **план опыта, измерений ещё нет.** Опыт разрешён решением D5
([ROADMAP](ROADMAP.md), раздел 3) и входит в этап 5 карты. Он проверяет главное неизмеренное
допущение лучшего кандидата этапа 4 — проверки ответа самим плательщиком (ППС,
[VERIFICATION_SEARCH](VERIFICATION_SEARCH.md), разделы 3.2 и 5.2).

## 1. Что проверяется

Плательщик, у которого есть модель, должен одним проходом пересчитать запрос и полученный ответ
и получить **те же самые биты**, что исполнитель при генерации. Это возможно, только если вся
арифметика модели задана целыми числами с закреплённым округлением: сумма целых не зависит
от порядка сложения, пока нет переполнения. Опыт отвечает на пять вопросов, критерии
опровержения закреплены до запуска:

| Опыт | Вопрос | Что его опровергает |
|---|---|---|
| О1 | Совпадают ли биты на разных видеокартах и на процессоре | Хотя бы один различный бит логитов, выбранного токена, причины остановки или контрольных хешей при одинаковом входе. Перед выводом — поиск первого расхождения и повтор на кратчайшем входе. Вывод относится только к испытанным устройствам и версии реализации |
| О2 | Совпадают ли биты при генерации по одному токену и при одном проходе по готовой последовательности на одной карте | Любой различный бит, включая хеш рекуррентного состояния слоёв Gated DeltaNet в контрольных точках |
| О3 | Сколько стоит проверка ответа по сравнению с его генерацией | Медиана доли `ρ(1)` больше 5% хотя бы для одной из четырёх заранее названных пар длин запроса и ответа при пакете 1. Пакеты 8 и 32 измеряются отдельно |
| О4 | Насколько целочисленный профиль медленнее обычного 8-битного на той же карте | Медиана замедления больше 1,25 раза в сопоставимой ячейке (порог диагностический: решают О3 и О5) |
| О5 | Сколько теряется качества | Потеря точности больше 3 процентных пунктов на 320 заранее выбранных задачах (по 64 из четырёх разделов MMLU и из русского MGSM) по сравнению с обычным 8-битным профилем той же модели |

Расчётные 1,2–3,8% из этапа 4 результатом О3 не считаются: их подтверждает или опровергает
только этот опыт.

## 2. Модель и оборудование

- **Модель:** официальный репозиторий Qwen/Qwen3.5-4B на Hugging Face, закреплённая ревизия
  `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`. Два файла весов по 5 329 398 688 и 3 990 429 408
  байт, всего около 9,3 ГБ. После загрузки сверяются SHA-256 из описи репозитория.
- **Архитектура** (по опубликованному `config.json`): 32 блока, скрытый вектор 2560, MLP 9216.
  Каждый четвёртый блок (индексы 3, 7, …, 31) — полное внимание: 16 голов запроса, 4 головы
  ключей и значений, размер головы 256, выходной гейт, поворот первых 64 координат. Остальные
  24 блока — Gated DeltaNet: рекуррентное состояние 32 × 128 × 128 на блок, причинная свёртка
  глубины 4. Словарь 248 320, входная и выходная матрицы общие. Обычный трансформерный
  «INT-канон» из этапа 4 для неё недостаточен; профиль задаётся заново (раздел 3).
- **Устройства:** RTX 2060 6 ГБ (Turing) на домашнем Linux сопровождающего; RTX 4070 Laptop
  8 ГБ (Ada) на компьютере владельца; процессор как третий независимый исполнитель. По согласию —
  устройства других участников через мини-агента.
- **Память** [расчёт]: основные 8-битные веса — 4010 МиБ. При пакете 1 и длине до 3000 токенов
  всё помещается в 6 ГБ; пакет 32 при длине 3000 требует около 7064 МиБ ещё до рабочих буферов
  и на RTX 2060 возможен только с переносом истории в оперативную память.

## 3. Целочисленный профиль

Профиль получает отдельное имя и версию и замораживается до О1–О5. Основа — числовой граф
из проекта ChatGPT с исправлениями обоих критиков:

1. **Веса и активации.** Веса 8-битные построчно, масштаб строки — точное двоичное число.
   Активации 16-битные с фиксированной точкой (1024 = единица). Округление одно для всех
   операций: к ближайшему, половина — к чётному, по модулю с возвратом знака.
2. **Нормировки и нелинейности** (RMSNorm, L2, SiLU, сигмоида, softplus, экспонента) — целые
   формулы с целым квадратным корнем и таблицы. Таблицы строятся вне программы с доказанным
   правильным округлением (MPFR) и публикуются с SHA-256.
3. **Полное внимание.** Оценки, экспонента по таблице, доли в 16 битах. Критик ChatGPT нашёл
   в исходном проекте ошибку: при одинаковых значениях добавление ещё одного такого же ключа
   меняло выход с 1365 на 683. Исправление: делить взвешенную сумму на сумму самих округлённых
   долей, тогда постоянное значение сохраняется точно.
4. **Gated DeltaNet.** Затухание, поправка и обновление состояния — пять целых присваиваний
   на каждый токен в одном каноническом порядке по времени. Формула из проекта DeepSeek
   описывала другую рекурсию и отвергнута. Ускоренная «блочная» форма допускается только
   если воспроизводит те же биты на каждом токене.
5. **Выбор токена.** Максимум по паре (оценка, −номер) по всему словарю, жадно. Отдельный режим —
   канонический Gumbel-max с псевдослучайностью HMAC-SHA256 от семени запроса (D22).
   Остановка — первая причина: EOS или лимит.
6. **Границы переполнения** заданы для каждого накопителя; где 32 бит мало, используются 64.
   Отдельные тесты проверяют крайние значения.

Все неоднозначные места («развилки») закрываются до первого запуска чтением исходника модели
закреплённой версии Transformers; хеш этого исходника входит в манифест профиля.

## 4. Порядок работ

1. **P0, подготовка (2–4 дня).** Загрузка и сверка модели; ведомость всех тензоров; закрытие
   развилок по исходнику; таблицы; контрольные векторы с ручными значениями.
2. **Урезанный шаг (1–1,5 недели).** Эталон на процессоре для всей модели на коротких входах;
   сверка с обычным вычислением в плавающей точке (только чтобы поймать ошибку импорта,
   не для О1/О2). Простая версия для видеокарты без тензорных ядер. Ответы О2 на одной карте
   и О1 «процессор против RTX 2060» на коротком контексте. Затем тот же пакет на RTX 4070
   Laptop — первый ответ О1 для двух разных видеокарт.
3. **Полный шаг (3–4 недели).** Быстрые 8-битные умножения, слитное ядро рекурсии DeltaNet,
   пакеты 1/8/32, опыты О3, О4, О5, повтор на втором устройстве.

Вся работа идёт в отдельном каталоге на домашнем Linux, с собственным окружением Python
(CuPy с библиотеками CUDA 12 из пакетов pip, без системной установки). Действующие службы
и каталоги других опытов не затрагиваются. Общая оценка — 4–6 недель работы одного
разработчика; главные риски — цена рекурсии DeltaNet (её покажет О3), неоднозначности
до P0 и поддержка Qwen3.5 в обычных движках для О4/О5.

## 5. Что будет опубликовано

Для каждого запуска: манифест профиля и версий, входы, хеши логитов и состояний по слоям,
сырые времена и условия измерения, исходные сбои вместе с исправлениями. Совпадение битов
относится только к испытанным устройствам и версиям. Результат каждого опыта вносится в карту
(этап 5) и в этот документ; опыт считается завершённым, когда его повторил второй участник.
