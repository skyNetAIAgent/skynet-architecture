# Задания для исследовательских агентов

[English](../../tasks/README.md) · [中文](../zh/TASKS.md) · [Español](../es/TASKS.md) · [Français](../fr/TASKS.md) · [Deutsch](../de/TASKS.md) · [Italiano](../it/TASKS.md) · **Русский** · [Português](../pt/TASKS.md) · [العربية](../ar/TASKS.md)

В этой папке лежит работа, которую берут [исследовательские агенты](../../agent/README.md):

- [`index.json`](../../tasks/index.json): текущий список заданий;
- `index.json.sig`: его подпись (агенты игнорируют список без действительной подписи);
- [`context/`](../../tasks/context): замороженные тексты, которые цитируют ИИ-вопросы.

Результаты публикуются комментариями в задаче отслеживания каждого задания и сводятся в
[`results/`](../../results) программой `tools/collect_results.py`.

## Что такое задание

Задание — это данные: имя встроенного в агент расчёта («ядро»), его
параметры и число независимых частей («порций»), на которые делится работа. Задание
не может нести в себе код. Новый вид расчёта требует нового подписанного выпуска агента.

```json
{"id": "exit-a-honest-check", "kernel": "exit-scam-a", "kernel_version": 1,
 "units": 256, "redundancy": 2, "issue": 12,
 "params": {"H0": 1200, "q": [0, 1], "cap_third": false, "batches": 2, "n_max": 200,
            "sizes": {"mode": "grid", "points": 48}}}
```

Планировщика нет. Каждый агент выбирает случайную порцию, которую ещё не делал. Попадание
нескольких агентов на одну и ту же порцию — так и задумано: все вычислительные ядра — это
точная целочисленная арифметика, поэтому одинаковая работа даёт одинаковые цифры на любом
устройстве, а порция считается подтверждённой, когда `redundancy` разных учётных записей
GitHub опубликуют одинаковый хеш. Разные хеши для одной порции — это конфликт, который
разрешает ведущий, пересчитав её.

## Встроенные расчёты в агенте 0.1

| Встроенный расчёт | Что он считает | Источник |
|---|---|---|
| `selftest@1` | Фиксированная целочисленная нагрузка; каждое устройство должно вернуть один и тот же отпечаток | [selftest.py](../../agent/skynet_agent/kernels/selftest.py) |
| `exit-scam-a@1` | Точная ожидаемая выплата участнику, который сдаёт поддельные результаты и уходит, по семейству стратегий; сообщает стратегии, которые превосходят честный уход | [exit_scam_a.py](../../agent/skynet_agent/kernels/exit_scam_a.py) |
| `lottery-b@1` | Точная вероятность убыточного месяца или квартала, когда оплачиваются только проверенные задания | [lottery_b.py](../../agent/skynet_agent/kernels/lottery_b.py) |
| `ai-answer@1` | По желанию: вопрос для локальной ИИ-модели, которую запускает участник | [ai_answer.py](../../agent/skynet_agent/kernels/ai_answer.py) |

Каждый файл с исходным текстом начинается с точной модели, которую он реализует, чтобы
любой мог независимо пересчитать результат.

## Задания, опубликованные сейчас, и зачем

Все они касаются главного открытого вопроса проекта: можно ли дёшево сделать обман
бесполезным ([OPEN_QUESTIONS, Q1](../../docs/OPEN_QUESTIONS.en.md)).

| Задание | Вопрос |
|---|---|
| `selftest-1` | Работает ли конвейер на вашем устройстве? |
| `exit-a-honest-check` | Без сговора есть ли способ заработать на подделках до ухода? Проект говорит, что нет |
| `exit-a-uniform-h399`, `exit-a-uniform-h1200` | При одинаковых мелких заданиях: при какой доле сговорившихся проверяющих уход с подделками окупается? Оценка проекта — около 91% |
| `exit-a-uniform-cap-h399` | То же с предложенным ограничением «не более трети ожидающей суммы в работе», в три волны |
| `exit-a-sizes-cap`, `exit-a-sizes-nocap` | То же, когда задания могут быть любого размера, с этим ограничением и без него |
| `lottery-b-table` | Если оплачиваются только проверенные задания, как часто у небольшого участника бывает убыточный месяц? |
| `ask-variant-b-attack` | Для локальных ИИ-моделей: найти новую атаку на правило «сеть платит только за проверенную работу» |

Это расчёты по правилам, как они записаны в проектных документах. Это не измерения
оборудования и не эксперименты с сетью. Задания-измерения (например, дают ли целочисленные
вычисления одинаковые биты на разных видеокартах) будут опубликованы только после того,
как ведущие проекта откроют эксперименты.

## Предложить задание

Откройте задачу с заголовком `[Task] …` и напишите:

1. на какой вопрос отвечает расчёт и к какому открытому вопросу он относится;
2. точную модель, чтобы её можно было независимо пересчитать;
3. какой встроенный расчёт и какие параметры его выполнят или что должен считать новый
   встроенный расчёт;
4. как будет замечен неверный или подделанный результат.

Ведущие проверяют задание командой `tools/sign_tasks.py --check`, добавляют его в `index.json`
и подписывают список. Подписать может только держатель ключа выпуска; см.
[docs/RESEARCH_AGENT.md](../../docs/RESEARCH_AGENT.md).
