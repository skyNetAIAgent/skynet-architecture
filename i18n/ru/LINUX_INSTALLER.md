# Установщик для Linux

[English](../../installer/linux/README.md) · [中文](../zh/LINUX_INSTALLER.md) · [Español](../es/LINUX_INSTALLER.md) · [Français](../fr/LINUX_INSTALLER.md) · [Deutsch](../de/LINUX_INSTALLER.md) · [Italiano](../it/LINUX_INSTALLER.md) · **Русский** · [Português](../pt/LINUX_INSTALLER.md) · [العربية](../ar/LINUX_INSTALLER.md)

Запустите один файл со страницы Releases проекта от имени своей учётной записи.

```sh
sh skynet-agent-install.sh
```

Этот файл содержит подписанный выпуск агента. При установке его подпись Ed25519 и хеши файлов проверяются без подключения к сети. Если в PATH есть Python 3.9 или новее, установка использует этот интерпретатор. Иначе нужна закреплённая сборка CPython под glibc для x86_64 или aarch64. **Оба хеша пока не закреплены. Для этой сборки нужен системный Python.**

Онлайн-установщик использует ту же процедуру установки. Если закреплённый хеш проверен, он может скачать подходящую среду выполнения из python-build-standalone и проверить SHA-256 перед распаковкой. Переносимые интерпретаторы находятся в `$XDG_DATA_HOME/skynet-agent/python/<sha256>`, обычно `~/.local/share/skynet-agent/python/<sha256>`. Команда в `~/.local/bin` и пользовательская служба systemd используют выбранный исполняемый файл.

```sh
curl -fsSL https://raw.githubusercontent.com/skyNetAIAgent/skynet-architecture/main/agent/install.sh | sh
```

## Запуск и удаление

В терминале нажатие Enter на первом запросе запускает службу сейчас и при входе в систему. Нажатие Enter на втором оставляет её привязанной к сеансам входа. Без терминала установка пропускает запросы. Эти команды задают выбор явно.

```sh
sh skynet-agent-install.sh --autostart           # Run now and at sign-in
sh skynet-agent-install.sh --autostart --linger  # Also run before login and after logout
sh skynet-agent-install.sh --no-autostart        # Install for manual use
```

Службе нужен работающий пользовательский менеджер systemd. Подписанный модуль записи службы версии 0.2.2 поддерживает пути с пробелами. Если путь к интерпретатору или агенту содержит двойную кавычку, обратную косую черту, знак доллара, знак процента или перевод строки, установка предложит запустить вручную. Если локальная политика запрещает постоянную работу после выхода, установка сообщает об этом, и служба всё равно работает во время сеансов входа. Постоянную работу для всей учётной записи можно отдельно изменить командой `loginctl disable-linger "$(id -un)"`. При ручной установке начинайте работу командой `~/.local/bin/skynet-agent run`.

```sh
~/.local/bin/skynet-agent selftest
~/.local/bin/skynet-agent version
~/.local/bin/skynet-agent uninstall --yes
```

При удалении служба выключается, ей отправляется запрос на остановку, и установка ждёт освобождения блокировки агента. Ваш ключ устройства, «исходящие», ожидающие отправки записи для ретрансляторов и настройки остаются в папке агента для переустановки. Чтобы также стереть сохранённые данные агента, используйте `uninstall --yes --purge`. Постоянная работа — это настройка всей учётной записи, и она сохраняется после удаления.

## Сборка и проверка

В корневой папке репозитория используйте Python 3.9 или новее на машине сборки.

```sh
sh installer/linux/build.sh
shellcheck -s sh agent/install.sh installer/linux/build.sh installer/linux/smoke.sh
dash -n installer/linux/skynet-agent-install.sh
python3 -I -m unittest discover -s agent/tests -t agent/tests
```

Сборщик проверяет подлинность выпуска открытым ключом из `agent/install.py` и создаёт `installer/linux/skynet-agent-install.sh`. Чтобы включить переносимый Python, проверьте каждый исходный архив по отдельности и запишите его SHA-256 в `python.lock` (по одному значению в строке). Только для пустой записи CI может передать проверенный хеш через `SKYNET_PYTHON_SHA256_X86_64` или `SKYNET_PYTHON_SHA256_AARCH64`. Это настройки времени сборки. Сборщик проверяет и встраивает каждый закреплённый архив. Чтобы собрать без сети с закреплёнными хешами, используйте `sh installer/linux/build.sh --runtime-dir /path/to/archives`.

Рабочий процесс установщика для Linux запускает этот файл от имени пользователя без прав администратора при отключённой сети. В Ubuntu 24.04 проверяется системный Python. В Debian 12 slim проверяется переносимый интерпретатор, когда хеш для x86_64 доступен, и проверяется отказ, когда он ещё не закреплён. При успешной установке выполняется самопроверка, сообщается версия и проверяются оба способа удаления. Рабочий процесс загружает скрипт как артефакт сборки для ручного распространения.
