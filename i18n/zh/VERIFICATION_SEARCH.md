# 寻找不依赖合谋份额的验证

[English](../../docs/VERIFICATION_SEARCH.en.md) · **中文** · [Español](../es/VERIFICATION_SEARCH.md) · [Français](../fr/VERIFICATION_SEARCH.md) · [Deutsch](../de/VERIFICATION_SEARCH.md) · [Italiano](../it/VERIFICATION_SEARCH.md) · [Русский](../../docs/VERIFICATION_SEARCH.md) · [Português](../pt/VERIFICATION_SEARCH.md) · [العربية](../ar/VERIFICATION_SEARCH.md)

状态截至 2026 年 11 月 24 日。

本文档是模型委员会针对路线图阶段 4（“寻找不依赖合谋份额的保证”，[ROADMAP](ROADMAP.md)，第 4 节）的成果。委员会寻找一种由每个节点自行执行的验证，使得其他验证者的同意或合谋都不起决定作用。寻找针对两类工作：Qwen 模型对用户请求的回答，以及微调步骤。

**文档状态。** 这是推理和按公式计算的结果，而非测量。没有为此进行模型实验、网络启动、证明系统运行或模型检验（model checking）。参与者和评审者只运行了简短的算术程序和在 CPU 上的小型穷举；ChatGPT 作品中的两个此类穷举由两位评审者重复，校验哈希一致。标有 [计算] 的数字由明确列出的参数按公式得出。模型和显卡的参数由参与者自行填入；没有任何作品将其与已发布的 Qwen3.5-4B 或约 27 十亿参数模型的配置核对过。**只有 [ROADMAP](ROADMAP.md) 第 3 节中的决定 D1–D25 才是已采纳的决定。** 此处其余一切均为委员会的评估。评审者存在分歧之处标注“有争议”。

**如何阅读。** 第 1 节说明寻找什么以及在什么条件下。第 2 节说明什么已被证明不可能，以及哪些不可能性论断已被驳倒。第 3 节和第 4 节分别分析模型回答和训练步骤的机制，包括最佳候选及其限制。第 5 节说明哪些尚未被证明，以及哪些实验和计算将解决它。第 6 节是给所有者的问题。第 7 节是参与者。

**简要总结。**

1. **模型回答。** 只有当整个回答由自身资金攸关的付款人亲自验证时，才存在不依赖合谋份额的验证。最佳候选是“PPS”：付款人用一次遍历将请求和已完成的回答在精确整数配置中重新计算，付款仅来自其预付款，对错误证明的争议由每个节点验证。计算价格为生成时间的 1,2–3,8%，但仅在每次生成一个回答时成立 [计算]。该候选不覆盖没有设备的消费者，并依赖于未经测量的位一致性。
2. **训练步骤。** 未找到在约 20% 范围内、不依赖合谋份额的步骤本身验证。六份作品和三位评审者都同意这一点。
3. **训练唯一幸存的道路**改变了付费对象：网络为模型在更新固定之后选定的考试上取得的已证明改进付费。根据决定 D18，这条道路作为新付费单位的候选进行研究，但尚未被采纳；需要计算、实验以及评审者发现的修正。
4. **起决定作用的是实验 D5**（整数 Qwen3.5-4B 在两块显卡上以及两种计算模式之间的位一致性、时间、质量）**和第 5.3 节中小型代理的计算**；据此对训练付费作出最终决定（D18）。

原始文档：决定 D1–D17 和阶段 4 见 [ROADMAP](ROADMAP.md)；对手模型和 D1 的形式化表述见 [THREAT_MODEL](THREAT_MODEL.md)，第 1.5 节；方案 A 和 B 见 [CURRENT_DESIGN](CURRENT_DESIGN.md)；[OPEN_QUESTIONS](OPEN_QUESTIONS.md)；[PILOT_RESULTS](PILOT_RESULTS.md)；[强制性要求](../ru/REQUIREMENTS.md)。参与者还阅读了项目此前关于精确算术、sumcheck/GKR、Brakedown 以及 LoRA 见证代价的研究（研究档案中的 `LORA_*` 和 `HONESTY_RESEARCH_GATE` 文档；它们不属于本仓库）。参与者当时尚未有决定 D6–D17：它们是在同一天通过的。在汇总时，这些决定被应用于作品的结论；凡决定改变结论之处，均已直接说明。

## 1. 问题设定

### 1.1. 寻找什么

寻找一种过程，由节点根据联盟无法伪造的数据自行执行：任务输入、已固定的模型、已固定的规则，以及可能的数学证明。节点的决定不应依赖其他节点的签名和裁决。于是，参与合谋的验证者占比 `q`（包括 `q = 1`）不影响决定。

两类工作：

- **（a）模型回答**：约 4–27 十亿参数的 Qwen 对用户请求的回答；
- **（b）微调步骤**（LoRA 或全量）在给定的数据批次上。

### 1.2. 强制性条件

| 条件 | 它对验证意味着什么 |
|---|---|
| **D1** | 对于任何联盟（包括账户为空的新手和任意数量的密钥），任何虚假申报相对不作为（`Δ₀ ≤ 0`）和相对诚实工作（`Δч ≤ 0`）的期望收益都不大于零。**两个**不等式都需要满足（[THREAT_MODEL](THREAT_MODEL.md)，第 1.5 节）。方案 B 中类似 `R·q^k` 的有限正泄漏不可接受 |
| **D2** | 只为可验证的结果付费。工作时间、申报的算力和已开启的设备都不构成依据。执行者获得正确结果的方式（缓存、另一台机器）并不重要 |
| **D4** | 验证是自动的，没有投票；每个节点按已固定的规则指纹自行执行 |
| **D6** | 危害纳入 D1：虚假回答不应作为已验证的结果交给用户，虚假步骤不应进入模型。结果只有在经过不依赖合谋份额的验证之后才能使用，否则必须明确标记为未验证 |
| **D7** | 需要不依赖合谋份额的验证。不允许把 D1 弱化为“只要合谋者少于 `q*`” |
| **D8** | 只有被抽签指派的验证者和就自身请求提出争议的用户可以争辩。没有押金。其余人可以在公告板上报告怀疑，但无权停止付款 |
| **D15** | 可以复制的简单重算不予付费 |
| **R5** | 没有任何押金、出资和罚款。只能损失尚未到期的奖励（“待结算金额” `H`） |
| **价格基准** | 验证附加成本约为请求工作的 5%，训练约为 20%。这些是基准，不是已确认的要求 |

相关决定：D9（训练计划由规则从目录和考试结果导出，积分按任务内容一次性发行）、D10（交换通过一条日志记录完成）、D12（窗口按网络活跃时间计算）、D14（争议价格按最便宜的二层网络计算）、D16（诚实的硬件故障不受惩罚）、D17（方案 B 中请求付款仅来自用户支付）。

统计抽样、对硬件安全区的信任以及按要求的微小密码学错误都是假设：可以提出，但必须直接说明。

## 2. 下界：什么已被证明不可能

### 2.1. 评审者确认的边界

这些是关于验证**类别**的论断。其中任何一个都不排除所有可设想的验证；没有人证明适用于所有算法的通用价格下界。

1. **不可区分性。** 如果节点仅根据其他节点的消息接受结果，那么当所有这些消息的作者合谋时，存在一个它会接受的虚假结果：联盟会发送与诚实结果相同的签名和指纹。当 `q = 1` 时，节点只受自己验证过的内容保护。（claude1，引理 1；claude2，3.1；gpt2，9.4；ds2，6.1。所有评审者同意。）
2. **“每个节点自行”的规模。** 如果共同状态的变化（积分发行、权重）必须对 `N` 个全节点中的每一个都受到保护，那么其中每个节点都要验证每一个这样的结果，总价格不低于 `N·v`，其中 `v` 是一次验证的价格。要在 5% 或 20% 以内，当 `N = 1000` 时需要 `v/W ≤ 5·10⁻⁵` 或 `2·10⁻⁴` 的工作量 [计算]。由此有三种获得独立于合谋的方法：由唯一资金攸关的参与者决定；验证被压缩（简短证明或小型考试）；结果根本不改变共同状态。（claude1，引理 2；claude2，3.4；gpt1，§2；ds2，6.1。所有评审者同意；评审者 ChatGPT 把 ds2 的公式修正为 `1 + n·a` 而不是 `(1 + a)·n`。）
3. **无编码的单元抽样。** 如果节点平均读取 `N` 个可独立替换的单元（层、位置、序列）中的 `s` 个，那么存在一个它验证概率不超过 `s/N` 的单元；其替换以不低于 `1 − s/N` 的概率通过。（claude2，3.2；gpt2，9.2；gpt1，5.4；claude1，I2。评审者 Claude 指出，对于硬币依赖于轨迹根的验证者，严格性存在缺口；结论不变。）
4. **抽样验证与执行者边际。** 对于成本为 `c_σ`、待结算金额为 `H` 的虚假申报 `σ`，D1 相对不作为要求 `π(σ) ≥ (R − c_σ)/(R + H)`，其中 `π` 是发现概率。对于廉价伪造和空账户，需要 `π ≈ 1`，即完整验证。对于几乎诚实的伪造，在边际 `m` 下需要不低于 `m/(1 + m)` 的验证比例。对于 `H > 0` 的密钥，在验证 `L + 1` 个块中的一个时，需要 `H ≥ R·((L+1)/m_s − 1)`：在一个可验证块下，36 层为 36R，64 层为 64R [计算]。节点的新鲜随机性使 `π` 独立于合谋，但不使其等于一。（claude1，引理 3；claude2，3.11，独立得出。所有评审者同意。评审者 ChatGPT 澄清：在强制验证输出块时，一次几乎免费的尝试的阈值为 35R。）
5. **域上的固定线性检查。** `t < n` 个预先固定的线性检查有共同的非零核：来自该核的错误它们看不到。在固定之后选取的新鲜均匀向量以不超过 `1/p` 的概率放过固定的非零错误。在有界整数上该下界不适用（见 2.2 第 3 点）。（gpt1，5.2；gpt2，9.1；claude2，3.5；ds2，5.2；claude1，B4。）
6. **零错误等价于确定性。** 在任何随机性下都没有误接受的验证，通过固定随机性变为确定性验证。（claude2，3.6。）
7. **完全合谋下的共同随机性。** 当 `q = 1` 时，所有节点共同的随机性只能来自网络外部（外部信标或 Fiat–Shamir）；SkyNet 节点之间的承诺交换无济于事。不同节点的个人随机性给出不同决定，无法得到统一计算。（claude2，3.8；gpt2，6.1。评审者 ChatGPT 补充：信标必须不可偏置、可访问，并严格在区块最终接受之后揭示；这已是 [THREAT_MODEL](THREAT_MODEL.md) 中的攻击 1.5 和 N13。）
8. **免费重复。** 如果尝试可以几乎无偿地重复（例如随机性由申报本身的哈希导出），成功概率随尝试次数增长。Fiat–Shamir 不能用于单元选择。（claude2，3.3；ds2，5.1。）
9. **自行构建结果的验证者。** 如果节点自己计算整个状态，只读取申报以作比较，那么去掉比较后就得到做同样工作的诚实执行者。因此这种验证的成本不低于最优工作的 100%。只有带提示的验证才可能便宜：现成的回答、轨迹或证明。（gpt2，9.5。评审者 Claude 和 DeepSeek 称这是通用下界的最佳表述。）
10. **获胜 token 的证书。** 对于一般位置的隐藏状态，要证明获胜者，必须获得关于词表中每个可能获胜行的信息。最坏情况下要验证整个词表。（claude1，B6；gpt2，9.3。）
11. **私有输入。** 没有请求的外部节点无法验证回答，除非有零知识证明。评审者 ChatGPT 澄清了下界：隐藏承诺连同此类证明可能传递所需的性质，引理并未排除这一点。（claude2，3.7；ds2，6.2；gpt1，§1。）

### 2.2. 被评审者驳倒的不可能性论断

1. **“字面 D1 要求错误恰好为零”**（ds1，F1）。只有当尝试毫无成本时才成立。如果随机性是外部且不可预测的，而每次尝试都需要新的固定并花费 `c_min > 0`，那么当 `ε ≤ c_min/R` 时 `Δ₀ ≤ εR − c_min ≤ 0`（claude1，引理 4；ds2，5.1）。ds1 自己的候选也依赖错误大于零的哈希。三位评审者都驳倒了它。评审者 ChatGPT 的保留：项目尚未确定任何联盟最便宜尝试的价格下界，因此小错误只在条件下与 D1 相容（第 6 节问题 2）。
2. **“验证现成回答按定义花费 +100% 时间”**（ds1，F2）。对于现成回答不正确：在一次遍历验证所有位置时，权重只读取一次，而不是每个 token 读一次。按运算数量，验证确实等于生成，但按时间，在每次生成一个回答时它可能快数十倍。此外，ds1 比较了不可比的权重配置。三位评审者都驳倒了它。
3. **“精确线性验证需要不少于 `N` 个形式和 `N²` 次运算”**（ds1，F3）。两方面都不对：固定之后的新鲜系数以约 `Q^(−s)` 的概率放过，而在有界整数上，当 `B > 2U` 时一个带位打包 `Σ y_i·B^i` 的形式就足够（gpt1，5.3；gpt2，6.2）；单位矩阵以 `O(N)` 读取坐标。三位评审者都驳倒了它。
4. **“回答验证的最小流量等于计算轨迹的大小”**（ds2 引理 5.3 的推论）。验证现成回答只需要回答的 token，而简短证明的验证者读取证明和根，而不是数据本身。三位评审者都驳倒了它。
5. **“任何诚实生成都必须执行与一次遍历验证同样多的运算”**（claude1，§4.1 和 B5）。这是验证价格的上界，而不是下界（评审者 Claude），而且如果执行者有合法的现成结果缓存，它不成立（评审者 ChatGPT）。
6. **“没有秘密随机性或密码学，就不可能有廉价的精确验证”**（claude2，3.5）。反例是在有理数上精确的岭回归正规方程可以确定性地验证（评审者 ChatGPT）。

### 2.3. 有争议或有条件的边界

- **考试规模 `n ≳ 2σ²·ln(1/ε)/δ²`**（claude2，3.10）。评审者 Claude 和 DeepSeek 将其作为工作估计使用。评审者 ChatGPT 表明，仅凭一个方差无法导出对任意分布都必要的 `n`：需要给定的备择假设和独立的抽样单位。**有争议**：可作为所述模型中的估计，而非定理。
- **完整证明的定量障碍**（claude2，3.9）：5% 的预算为每个非线性单元留下约 1–5 次域运算，20% 的预算留下约 6–18 次，而已知的舍入构造需要数十次，softmax 需要数百次 [在给定成本下的计算]。所有评审者同意，这是已知构造的边界，而非定理。

## 3. 模型回答（a）

### 3.1. 考虑过的所有机制

“价格”表示为相对诚实执行工作的附加成本；所有数字均为按作品参数得出的 [计算]。“结论”是经过三次评审并考虑 D6–D17 后的结果。

| 机制（作品） | 实质 | 保证与假设 | 节点数据 | 合谋与反例 | 价格 [计算] | 结论 |
|---|---|---|---|---|---|---|
| **每个节点完整重放**，对已完成回答的因果遍历（全部六份） | 持有输入的节点自行计算所有位置，并检查每个 token 和第一个停止原因 | 在精确配置、真实输入和正常内核下错误为零 | 请求、回答、模型、配置、种子 | 合谋无济于事：由自身重算决定 | 每个 `N` 节点约 100% 的运算；外部节点看不到私有请求 | 作为基准**成立**；在所有节点验证时不进入 5% |

### 3.2. 模型回答的最佳候选及评审者的修正

**候选。** 整个回答由付款人自己验证。如果他有能容纳模型的显卡，这就是 PPS（claude1）。如果没有显卡但有快速通道，这就是 M1（ds2），每个请求使用新鲜的秘密向量。两种情况下，已付费请求都不产生积分发行和权重（P0；这与 D17 一致），争议由每个节点根据错误证明裁定（I8）。为什么合谋无济于事：决定由唯一资金攸关的参与者作出；他拥有完整数据——请求、回答和模型；验证是完整的，而不是抽样的。

**没有这些修正，候选就不成立。**

1. **扣留回答。** 日志中需要放入回答的密文本身，而不仅是它的指纹：每个回答约 2–4 KB（评审者 Claude）。这与 D10 一致：通过一条日志记录交换。
2. **虚假争议。** “付款人 = 执行者”联盟可以创建任意多的小请求，并为每一个提交争议，而所有节点都会下载并重算。D8 用请求数量限制争议流，但自费请求不受这一限制。没有任何作品给出解决方案（第 5 节，任务 M9）。
3. **及时性和审查。** 付款人必须在网络上，并在窗口内及时公布证明，而日志必须接受它。窗口内的块审查依赖于日志外部验证者的诚实性。这是关于另一集合中合谋的假设，必须直接说明。对于付款人的手机，它最常被违反。按 D12，窗口按网络活跃时间计算。
4. **两端绑定。** 关于第一层的争议需要绑定到原始私有请求，关于最后一层的争议需要绑定到已付费的密文（评审者 ChatGPT）。
5. **停止条件。** 需要验证第一个停止原因。“最后一个 token 是 EOS 或已达到限制”这一条件会放过在提前 EOS 之后续写的回答（评审者 ChatGPT）。
6. **INT-canon 算术。** 规范中注意力概率与值的乘积在 int64 中累加。如果不在张量核心上执行，长场景 2000/1000 的价格会从 3,8% 增长到约 8%（评审者 Claude 的估计）；出路是把 16 位概率分解为两个 8 位半部。评审者 ChatGPT 还发现三个缺口：只允许一个键时，softmax 给出 65 536 的值，无法放入 16 位；RMSNorm 中的平方和可能使 int64 溢出（三个 `2³¹−1` 的分量已经超过 `INT64_MAX`）；需要明确的宽度、RoPE 位置和舍入顺序。该原则本身经得起这些修正。
7. **流式输出。** 按 D6，用户不应把未验证的文本视为已验证。在流式输出时，每个已显示的前缀都必须经过验证，此类验证的频率计入价格（gpt2，§1）。

**候选的限制。**

- 1,2–3,8% 的价格只在每次生成一个回答时成立。对执行者而言，把请求合并成批有利可图，而在批量 8–32 时，诚实的比较给出 8–48% [计算]。
- 该候选不覆盖没有设备的消费者。对于 27B，付款人需要不少于 13 GB 显存。按要求，主要消费者是没有设备的参与者。按 D6，他的回答只能以“未验证”标记给出；在这种情况下如何在不违反 D1 的前提下向执行者付费，没有任何作品解决。
- 一切都依赖于未经测量的假设 A1：不同显卡上的比特一致，**且**逐点解码与在单块显卡上遍历整条序列之间比特一致。如果 Qwen3.5 中有线性注意力的循环层，其并行形式的舍入不同，验证价格可能大约翻倍（claude1，3.4，在每步 10 µs 的假设下估计）。
- 争议会泄露请求：块输入几乎可逆地恢复文本。没有不泄露的争议。
- 能量未测量：在受计算限制时，显卡的功耗高于受内存限制时，因此按能量的份额可能高于按时间的份额。
- 加速器（区间证书、贪婪选择的获胜者证书、自有前缀缓存）只能叠加在完整验证之上，而不能代替它。

### 4.2. 训练步骤的最佳候选及其限制

**在 20% 以内、不依赖合谋份额的步骤本身验证并不存在。** 这是一个从不同方面得到确认的总体否定结果：规模 `N·v`、每步 64 GB–2 TB 的轨迹、比工作贵数十到数百倍的证明、逐元素运算的预算。

在**付费依据不变**的情况下，剩下两条路：完整重放转移（基准，每节点 +100%），以及长期来看对整个步骤的强制证明（T3）。对于 T3，需要具体的图、已证明的组合稳健性和完整估算；目前没有。

在**改变付费依据**时（所有者的决定，第 6 节问题 1），最佳候选是 T4 与 ODU 的结合，并加上评审者的修正：

1. 外部信标严格在所有更新固定和区块最终接受之后选择考试。
2. 阈值取自具有密码学上微小 `ε` 的统计界（如 T4），而不是 10%。
3. 考试用证明验证（ODU 框架），使价格不随节点数增长。
4. 损失由算术本身限制（配置中的最小概率），并且不截断，否则会为有害更新付费。
5. 重复的归因需要在不使用顺序证明链的情况下解决。没有任何作品解决这一点。

**限制。**

- 这不是步骤验证。考试看不到优化器矩，不证明更新的来源，也不排除在考试本身上的训练。
- 按 D6，虚假步骤不应进入模型。考试上的改进不能证明在罕见请求上没有危害和没有后门（[OPEN_QUESTIONS](OPEN_QUESTIONS.md) 中的 Q4）。该候选限制金钱收益，但不限制危害。
- 未知单个更新的诚实改进是否超过阈值：损失差的噪声 `σ` 未测量。如果不超过，诚实参与者得不到付款，R6 被违反。
- 更新很小的弱设备无法通过阈值；“所有空闲算力都在学习”只作为“在学习”成立，而不是“获得报酬”。
- 与 D9 的联系：训练计划已经由考试结果导出。这使考试成为核心的一部分，但没有解决能否为改进而不是步骤付费的问题。

## 5. 什么尚未被证明以及如何检验

### 5.1. 什么尚未被证明

1. 整数配置在不同显卡上以及逐点解码与单卡遍历整条序列之间的位一致性（A1，问题 Q2）。PPS、M1、区间证书和任何精确重放都依赖于此。
2. 在真实显卡上批量 1、8、32 时，现成回答的验证时间相对于生成时间；能量；线性注意力混合层的行为。
3. 整数 Qwen3.5-4B 配置相对于普通配置的质量和速度。
4. 区间证书和获胜者证书在真实权重上的价格。
5. 争议数据的可获取性、无押金时虚假争议的上限、日志的及时性和审查。
6. 对于为改进付费：诚实改进相对于阈值的量、无重复获胜的归因规则、无截断的损失界、考试证明的价格。
7. 对于步骤的简短证明：一个步骤的完整估算和端到端错误界。
8. Qwen3.5-4B 和约 27B 模型的精确配置：所有作品数字都是手工代入的。

| M17 | 小规模块上的高斯–牛顿步骤 | 显式有理矩阵 `J`、恒等式 `⟨Jx, z⟩ = ⟨x, Jᵀz⟩`、整数长度、细化次数、平局 | 新合约的价格 |
| M18 | 支付计算和恢复 | 有限穷举：一个任务编号、两个父状态、分叉、输入丢失、所有被指派者合谋、空账户 | 每个结果不超过一次支付；在接受之前不应用任何东西 |

## 6. 本阶段需要的决定

委员会不作出决定。以下是带委员会建议的问题。所有者委托维护者解决它们；决定 D18–D25 已于 2026 年 11 月 24 日通过，并记录在 [ROADMAP](ROADMAP.md) 第 3 节。每个决定都在问题之后给出。

1. **是否把训练付费依据改为“为已证明的改进付费”？** 按 D2，为可验证的结果付费；考试上的改进形式上就是这样的结果，但它是与已完成的步骤不同的对象。三份作品（claude1、claude2、ds1）认为它是主要候选，三份（gpt1、gpt2、ds2）认为它是另一种合约，而不是步骤验证。*委员会建议：* 允许把这条道路作为训练新付费单位的候选进行研究，但不称之为步骤验证。最终决定应在计算 M7、M8、M10–M12 和实验 O6 之后作出。条件：固定之后的外部信标、密码学上微小的 `ε`、无截断的损失、考试证明、无重复获胜的归因规则。按 D6 记录：改进不能证明没有危害。**已决定——D18：** 该道路作为新训练付费单位的候选进行研究，但未被采纳，也不称为步骤验证。采纳决定——在 M7、M8、M10–M12 和实验 O6 之后（O6 在 D5 之外，需要所有者许可）。模型仅按规则 D9 发行。对步骤本身验证（T3）的寻找继续进行。
2. **是否允许微小的密码学错误？** 要求中将其称为假设。作品 claude1、claude2、ds2 以及评审者 Claude 和 DeepSeek 认为，如果随机性是外部且不可预测的，且每次尝试的成本大于 `ε·R`，则错误 `2⁻⁴⁰…2⁻¹²⁸` 作为期望与 D1 相容。作品 gpt1、gpt2 和评审者 ChatGPT：对 D1 而言一个微小错误不够，需要已证明的最便宜尝试的价格下界。ds1 认为需要恰好为零。*委员会建议：* 在三个条件下接受微小错误作为明确列出的假设——外部信标严格在区块最终接受之后、禁止用 Fiat–Shamir 进行抽样、记录尝试价格的下界。没有这个决定，为改进付费和简短证明都不可能。**已决定——D19：** 在这些三个条件下允许微小错误作为明确假设，每次尝试不超过 `2⁻⁸⁰`，且 `ε·R` 小于已记录的尝试价格下界。带有 `q^k` 错误的普通抽样验证不因此被允许。
3. **允许哪种外部信标以及谁的信任？** 没有外部共同随机性来源，当 `q = 1` 时任何固定后抽样的方案都不工作（边界 2.1 第 7 点）。来源尚未选定（攻击 1.5 和 N13）。*委员会建议：* 选择若干独立来源，并把对它们的信任记录为假设。**已决定——D20：** 不少于两个独立的公开来源，值在最终固定之后预先指定的时刻取得，无权跳过。具体来源及其影响成本——在阶段 2。在选择方案之前不启用抽样。
4. **是否接受：对于模型回答，只有自行验证的付款人才有不依赖合谋的验证？** *委员会建议：* 是。对于没有设备的消费者，回答以“未验证”标记给出（D6 允许这一点），而委托验证是他自己的假设。需要单独决定如何在不违反 D1 的情况下向执行者支付这种回答：没有解决方案。**已决定——D21：** 是。网络不为未经验证的回答付费。没有设备的用户可以自行指派验证者；这是他自己的假设，网络不为他承诺 D1。对这种用户的 D1 保证仍是开放问题。
5. **是否允许为廉价精确验证而改变产品？** 这包括通过 Gumbel-max 的规范 token 选择（与通常的 top-p/top-k 抽样相比改变分布）、精确整数配置（可能降低质量）、有可验证结果的任务（公式、测试）以及带精确证书的新优化器（高斯–牛顿、岭回归）。*委员会建议：* 在实验 O5 和计算 M17 之后，作为计划的单独任务类型并带明确合约予以允许。**已决定——D22：** 在 O5 和 M17 之后，作为计划的单独任务类型并带明确合约予以允许。通常抽样仍可用，但标记为“未验证”。
6. **如何在没有押金的情况下限制付款人的虚假争议？** D8 用请求数量限制争议，但为自己支付请求的联盟会绕过这一限制。*委员会建议：* 在决定之前计算虚假争议的价格（M9）；委员会没有找到不需要押金的规则。**已决定——D23：** 先进行计算 M9。在选定无押金限制虚假争议的规则之前，不纳入 PPS。
7. **是否在日志中保存回答的密文？** 否则执行者可以扣留回答。*委员会建议：* 是，每个回答约 2–4 KB；这与 D10 一致。**已决定——D24：** 是，密文与接受记录一起作为一条日志记录写入。
8. **D1 的双向表述是否也适用于部分伪造？** 作品 claude2 询问，是否允许比诚实工作差但比不作为好的伪造。D1 在 [THREAT_MODEL](THREAT_MODEL.md) 第 1.5 节中的形式化表述已经要求两个不等式。*委员会建议：* 不改变；因此 VYa-S 和相对变体的 PVYa 被否决。**已决定——D25：** 不改变。
