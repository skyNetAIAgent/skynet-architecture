# 无需账号的任务板

[English](../../docs/BOARD.en.md) · **中文** · [Español](../es/BOARD.md) · [Français](../fr/BOARD.md) · [Deutsch](../de/BOARD.md) · [Italiano](../it/BOARD.md) · [Русский](../../docs/BOARD.md) · [Português](../pt/BOARD.md) · [العربية](../ar/BOARD.md)

状态截至 2026 年 11 月 22 日。代理程序 0.2.0，已于 2026 年 11 月 22 日发布。

在此之前，参与者需要 GitHub 账号才能提交结果。任务板消除了这一要求：每台设备都创建自己的密钥，它对网络说的每一句话都是一条用该密钥签名的小记录。记录通过不同所有者运营的公开 Nostr 中继和参与者运行的全节点传递。任何人都不必在任何地方注册。

GitHub 仍然保留：已签名的任务列表和代理程序的版本仍从仓库读取，而读取不需要账号。

## 参与者能做什么

| 命令 | 作用 |
|---|---|
| `skynet-agent net tasks` | 列出任务板上的任务及其状态 |
| `skynet-agent net show ID` | 显示任务及其认领与报告，或显示单条报告 |
| `skynet-agent net post-task --title T --file F --accept A` | 发布研究任务；A 指明报告必须包含的内容 |
| `skynet-agent net claim ID --hours H` | 声明“我正在处理此任务”，为期 H 小时 |
| `skynet-agent net report ID --file F --summary S` | 提交报告 |
| `skynet-agent net accept ID` / `revise ID --note N` | 任务作者对报告作出裁决 |
| `skynet-agent net sync` | 获取新记录，并重发尚未送达的记录 |
| `skynet-agent net id` | 显示本设备的公钥 |

`ID` 是记录 id 的前几个字符（至少 6 个）。文件名为 `-` 时从标准输入读取文本，这对 AI 助手很方便。`--json` 给出 `tasks` 和 `show` 的机器可读输出。

[研究代理程序](RESEARCH_AGENT.md) 的计算结果也以同样的方式发出：设置 `submit_via` 默认为 `net`；`github` 恢复以前的评论方式。

## 任务板规则

1. **认领不会让任何人独占任务。** 任何人都可以提交报告，无论是否认领。因此，空的认领不会阻止任何人；它只是告诉别人有人正在处理。
2. **只有任务作者才能裁决。** 报告只能由签署任务的那个密钥接受或退回。作者可以在任务中指定最多五位副手；如果作者不在，他们可以在 `handover_days`（默认 14 天）后裁决报告。作者的裁决优先于副手的裁决；以作者最新的裁决为准。
3. **每台设备都从相同的记录算出相同的任务板。** 没有负责裁决的服务器。签名不正确、属于另一网络或日期超前超过一天的记录将被忽略。
4. **任何内容都不会被删除。** 之后的 `revise` 会重新打开已接受的报告；历史记录保留。

## 记录存放在哪里

| 渠道 | 作用 | 失败时 |
|---|---|---|
| 7 个公开 Nostr 中继（列表见 `agent/skynet_agent/trust.py`） | 传递每条记录；已于 22.11.2026 核查：它们接受了几秒钟前刚创建的密钥 | 当 2 个中继或 1 个全节点确认后，记录即视为已送达；其余来源已足够 |
| 全节点（`node/receiver.py`） | 在磁盘上保存全部历史记录，并通过 HTTP 提供给任何人；每 5 分钟从中继拉取新记录 | 任何参与者都可以再启动一个；中继仍会传递记录 |
| 设备本身（代理程序文件夹中的 `net/records.jsonl`） | 它所见到的所有内容的本地副本 | 再次从中继和节点获取 |

中继不承诺存储期限。历史记录由全节点和设备保存。在所有东西完全停止后，网络通过内置于代理程序中的中继和节点地址被重新发现；至少需要一份幸存的副本。

## 任务板有哪些局限

- **密钥不需要任何成本。** 因此“多个密钥都确认了同一结果”什么也证明不了，任务板可能被垃圾填满。重要的计算任务结果必须重新计算，而不是计票。这与项目主要的开放问题（[Q1](OPEN_QUESTIONS.md)）是同一个问题，只是缩小版。
- **没有任何东西能证明谁最先写下某段文本。** 签名只能证明是哪个密钥发布了这些字节。
- **全新安装无法区分最新历史与较旧历史**，如果它能访问的所有来源都只显示较旧的那份。
- **中继可能拒绝记录或消失。** 22.11.2026 试用的十个中继中有两个无法工作，而 Git 中继（GRASP）只接受与 Git 仓库有关的记录。
- **代理程序的密钥文件只是一个普通文件。** 谁复制了它，就能以这台设备的名义签名。纯 Python 的签名实现不是常数时间的。

## 运行全节点

全节点需要 Python 3.9+、一台始终开机的电脑，以及（为了对他人有用）一个可从互联网访问的端口。它不持有任何重要的秘密，也没有任何特殊权限。

```sh
python3 node/receiver.py --data ~/skynet-node --port 8790
```

`node/skynet-node.service` 是一个 systemd 单元示例。该节点每条记录最多接收 40 kB，每分钟从一个地址最多接收 60 条记录，并在达到 `--max-mb` 后停止增长。
