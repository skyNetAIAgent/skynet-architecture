本文档是第五次模型委员会的成果。项目所有者逐字问道：

> «也许值得选择另一种策略？例如接入某种数学？这样就不必逐一检查所有东西，而是预测欺骗

## 1. 简要总结

1. **在规则公开时，“预测欺骗并只检查可疑者”并不能节省验证。** 验证规则对所有节点相同，且为欺骗者所知（D4）。他只会在检测器说“安全”的地方提交伪造，而在欺骗之前表现得像诚实者。已严格证明：检测器把伪造被检查的概率提高到诚实工作平均检查率之上的幅度，不超过它们可观测分布之间的距离（第 2 节）。因此预测、异常、基于历史的信任和图谱只能**增加**下界之上的验证，而不能把频率降到下界以下。六份作品和三位评审者都同意这一点。
2. **不可伪造的特征恰好有两个：** 答案被不可逆地固定之后精确重算的结果，以及待结算中的可燃烧金额——密钥尚未支付的奖励，在被抓获时消失。全部真实节省都来自第二个特征，而不是“智能”。
3. **针对模型回答找到的最佳策略：** 付款人自己用一次遍历验证其回答，而“验证与否”的决定由他在答案固定之后用**自己的秘密硬币**作出，概率不低于 `R/(R + H_lock)`。这里 `R` 是任务价格，`H_lock` 是执行者尚未成熟的奖励中在验证结束前不会成熟的那部分。空账户的新手回答总是被验证。于是，在第 4 节的条件下，无论其余各方合谋份额如何，包括完全合谋，伪造都无利可图。三位评审者中有两位支持这一策略；评审者 ChatGPT 倾向于对每个回答做完整验证（第 6 节）。
4. **而验证本身的代价是百分之零点几：** 约为工作的 0,005–2%，取决于调度和密钥负载；对于有危害限制的低活跃密钥，可达 6,7% [计算]。主要代价转移到精确配置上：在批次 1 时它比普通 8 位生成慢 1,5–1,8 倍，在批次 8 时慢 2,5–2,8 倍 [测量]。合计在批次 1 时为普通生成的 +50…+82% [计算]。5% 的基准卡在精确配置的速度上，而不是验证上。
5. **危害不能靠经济手段消除。** 破坏者不需要获利：在抽样验证下，他的一部分伪造会通过（在最便宜的调度下约为一半，第 4 节）。因此未验证的回答必须带有“未验证”标记，而“已验证”只在展示前完成完整验证之后才标注。对于训练步骤的新保证，委员会没有找到。
6. **没有设备的用户**不受这一策略保护：如果由随机的他人节点替他验证，泄漏等于 `R·q^k`，在完全合谋时等于全部价格（第 5 节）。这仍是 D21 的开放问题。
7. **所有者需要决定的事项：** 是否允许按硬币规则支付未验证的回答（D21、D11、D7）；如何处理与抽样验证不相容的免费诚实故障（D16）；是否采纳关于待结算金额“锁定”和受害者返还上限的新决定 D26；虚假争议规则（D23，计算 M9）仍是启用条件。问题在第 6 节中表述。

**符号。** `R` —— 任务价格；`c` —— 诚实工作的成本；`c_f` —— 伪造的成本（最坏情况几乎为零）；`H` —— 执行者密钥的待结算金额；`H_lock` —— 其中在本任务验证最终结果之前不会成熟的那部分；`p` —— 任务被验证的概率；`q` —— 验证者中合谋的份额；`k` —— 指派的验证者数量；`n_w` —— 成熟窗口内密钥的任务数；`ρ` —— 一次遍历验证回答的时间除以生成它的时间（批次 1 时为 0,10–0,40，批次 8 时为 0,26–0,64 [测量]）；`γ` —— 精确配置相对 llama.cpp Q8_0 的减速（批次 1 时为 1,5–1,8，批次 8 时为 2,5–2,8 [测量]）；PPS —— 付款人自行验证。`Δ₀` 和 `Δh` —— 伪造相对不作为和相对诚实工作的期望收益差；D1 和 D25 要求两者都不大于零。

## 2. 为什么在规则公开时“预测欺骗”不起作用

### 2.1. 通过全变差的边界

设验证决定由任意规则 `π(x)` 作出，取值从 0 到 1，其中 `x` 是网络或付款人在决定前看到的一切：回答时间、文本、统计、密钥历史、关系图。诚实工作产生的观测服从分布 `P`，伪造服从分布 `F`。于是

`E_F[π] − E_P[π] = Σ_x π(x)·(F(x) − P(x)) ≤ Σ_{x: F(x) > P(x)} (F(x) − P(x)) = TV(F, P)`。

不等式成立是因为在 `F > P` 处 `π ≤ 1`，在 `F < P` 处 `π ≥ 0`。量 `TV` 是全变差距离：两个分布总体上可区分的程度。由此（claude2 作品的定理 T4；gpt1 和 gpt2 有同样的不等式）：

1. **伪造被检查的频率不超过诚实工作的平均检查率加上 `TV`。** 如果伪造在观测上难以区分（`TV ≈ 0`），检测器检查它的频率就与诚实工作相同。
2. **面对知情的对手更糟。** 规则是公开的（D4），因此对手自己计算 `π`，并选择验证概率最低的那种观测。他最佳伪造被抓获的概率，等于他能廉价创造的那些观测中最小的 `π(x)`。
3. **对节省的推论。** 要使伪造无利可图，必须以不低于 `R/(R + H_lock)` 的概率检查它（第 4 节）。当 `TV ≈ 0` 时，对诚实工作也必须保持同样的频率，也就是没有节省。按 claude2 的估计，“智能”带来的收益不超过因子 `R/(R − c*)`，其中 `c*` 是最便宜的不可区分伪造的价格；在合理的 `c* ≈ 0,5R` 下不超过两倍，但 `c*` 由对手选择，且未被测量。
4. **密钥历史对欺骗时刻毫无说明。** 一个决定在下一个任务上欺骗的密钥，在该任务之前拥有与诚实者相同的历史（似然比恰好为 1；claude2 的定理 T5，gpt1 的反例）。因此序贯检验（Wald 的 SPRT、Page 的 CUSUM）、赌博机算法和贝叶斯“信任”只能在欺骗之后才发现它。claude1 的小型穷举表明：如果把基于信任的验证频率降到阈值以下 10%，就会出现有利可图的“积累信任然后欺骗”策略（60 个任务内 +1,7R…+2,5R），降一半时为 +14,4R…+19,4R [计算]。评审者 Claude 复现了这些数字，评审者 DeepSeek 在最近的模型中得到另一个数值（+0,085R），但符号相同（第 8 节）。

### 2.2. 基于测量 D5 的例子

最自然的廉价伪造是**同一个 Qwen 在 llama.cpp Q8_0 中运行**。精确配置比它慢 1,5–1,8 倍（批次 1）和 2,5–2,8 倍（批次 8）[测量]，因此伪造明显比诚实工作便宜。同时这是同一模型的回答：时间、风格、小模型下的困惑度都与诚实回答相同，而执行者可以自行增加延迟。如果 Q8_0 的回答与精确回答逐 token 一致，这就不是伪造：按 D2，重要的是结果。如果它至少在一个 token 上不同，只有精确重算才能发现，因为精确配置的位在任何已测试设备上都一致 [测量]。

评审者 ChatGPT 的保留意见：D5 测量的是精确配置与官方模型的接近程度（90 个位置中 90 个相同 token，逻辑值相关系数 0,9996 [测量]），而 Q8_0 伪造与精确配置在廉价特征上的接近程度未被测量。对保证而言这不重要：只要没有人展示出能区分每一种可用伪造与诚实回答的特征就够了。

### 2.3. 检测器仍然有用的地方

检测器、陷阱和网络分析是允许的，如果它们**只提高**验证频率：

- 作为付款人额外自愿验证的队列，这些验证不计入保证，但提高实际抓获率；
- 对付不优化行为的不谨慎破坏者；
- 用于诊断设备和驱动故障；参与者可以对自己的自检运行 CUSUM，并在损失待结算金额之前停止；
- 在非自适应错误流上，它们每验证小时能找到更多错误。gpt1 的例子 [计算]：伪造份额 2%、灵敏度 90%、误报 5% 时，验证 8,57% 的任务，抓获该类伪造的 90,2%，代价 1,80%，而均匀验证为 18,94%。但检测器未标记的那类伪造有 98% 的情况被放过。

还有反向攻击（claude2）：那些诚实回答看起来“异常”的请求，会迫使把验证花在诚实者身上。如果验证由引发它的人支付，这本身就受到限制；如果由网络支付，这就是负载转移。

## 4. 经受住评审的下界和公式

### 4.1. 单次伪造：阈值 `R/(R + H_lock)`，而不是 `R/H`

被抓获的伪造不予支付，并烧毁待结算金额（按 R5 不能扣除其他任何东西）。于是

`Δ₀ = (1 − p)·R − p·H_lock − c_f ≤ 0  ⇔  p ≥ (R − c_f)/(R + H_lock)`，

而在几乎免费的伪造下——`p ≥ R/(R + H_lock)`。相对于诚实工作，`Δh = Δ₀ − (R − c) ≤ Δ₀`，因此 D25 的第二个条件自动满足。新手 `H_lock = 0`，`p = 1`。最低频率 [计算，claude2]：`H_lock = R` 时为 0,5；`3R` 时为 0,25；`10R` 时为 0,0909；`99R` 时为 0,01；`4320R` 时为 0,000231。

claude1 的作品提出了规则 `p = min(1, R/H)` 并称之为精确。评审者 Claude 通过穷举表明，精确阈值是 `R/(R + H)`：用它时伪造的最大收益恰好为 0，而用 `0,99·R/(R + H)` 时已是 +0,225R 到 +0,299R [计算]。规则 `R/H` 含有余量。评审者 DeepSeek 指出，这一余量对危害有用：在 `R/H` 下，抓获前的期望伪造次数有限（约 `H/R + 1`），而在 `R/(R + H)` 下是无限的（第 4.4 节）。把哪个公式纳入核心尚未决定（第 8 节）。

### 4.2. 条件：金额在验证结果之前不成熟

只能烧毁在已证明争议时刻尚未支付的部分。如果 `H` 的一部分更早成熟，规则就失效。反例 [计算]：

- claude2：密钥 `H = 99R`，在结果之前成熟，在 `p = 1%` 时提交 `n` 次伪造；`n = 1` 时收益 0,99R，10 时 9,04R，100 时 36,6R；
- 评审者 Claude：密钥 `H₀ = 100R` 停止诚实工作并提交伪造，而付款人验证得很晚；`n` = 1、10、100、300 时收益 +0,99R、+9,1R、+49,7R、+74,4R。有“锁”（全部烧毁）时，同样的策略给出 −0,01R 到 −0,75R。

因此，任务 `i` 的频率分母只包含在 `i` 的争议最后期限**之后**成熟的那部分金额，而付款人的验证期限 `δ` 必须远小于成熟窗口 `W`；两个期限都按活跃时间计算（D12）。这是“及时验证”的假设；对于很少上网的手机，它最先被违反。

### 4.3. 离开前的伪造波

离开前的一批伪造，只有在下述规则下才被单次伪造公式覆盖：**“第一次被证明的抓获会烧毁密钥的全部未成熟金额，包括同一波的奖励”**。

- 没有这条规则时（gpt1）：在 `R = 1`、`B = 4R`、`d = 0,2` 时，10 次并行伪造中每次漏过都得到支付，而旧金额只损失一次，给出 `10·0,8 − 4·(1 − 0,8¹⁰) = +4,4295R`，尽管一次伪造给出零。如果抓获使整波作废，同样的策略给出 −2,49676R [计算；评审者已重复]。
- 评审者 ChatGPT 添加了第二个例子：在 `H = R`、`p = 1/2`、两次使用独立硬币的伪造且旧金额只扣一次时，收益为 `R/4` [计算]。这意味着协议必须原子地把密钥的所有未结承诺与其全部未成熟收入绑定。

在这条规则下，claude2 的证明（T2）成立：每次新的伪造把期望结果乘以 `(1 − p_j)·(1 + α_j/(H_lock + A)) ≤ 1`，其中 `α_j` 是未验证的支付，`A` 是已积累的可燃烧金额。按伪造次数归纳，对任何批次和任何自适应序列都有 `E[结果] ≤ H_lock`。对于均匀批次，同样可由 `(1 + R/H)ⁿ ≥ 1 + nR/H` 得出。在精确分数网格上的检查给出的最大超出恰好为 0 [计算]。

### 4.4. 委员会验证：因子 `1 − q^k`

如果抓获必须由 `k` 个指派验证者中的至少一个记录，而每个以概率 `q` 属于联盟，则抓获概率降到 `p·(1 − q^k)`，阈值变为 `p ≥ R/((R + H_lock)·(1 − q^k))`。当 `1 − q^k < R/(R + H_lock)` 时它不可行，`q = 1` 时总是不可行。在带委员会的抽签 B 中，新手每次尝试得到 `R·q^k`：当 `q` = 0,1 / 0,3 / 0,5 / 1 且 `k = 3` 时为 0,001R / 0,027R / 0,125R / R [计算]。这与对手模型一致。选择的独立性也是一个假设：当从 `N` 个参与者中选 `k` 个不同者、其中 `C` 个合谋时，完全合谋的概率为 `C(C,k)/C(N,k)`；在数据普遍不可得或选择性发放时，它可能达到 `q` 或 1（评审者 ChatGPT 按对手模型）。所有作品的结论：**频率必须由其决定受到保护的人执行**——付款人保护自己的钱，每个节点保护自己的账目。

### 4.5. 危害：未被抓获的份额

破坏者不需要获利，因此危害以其未被抓获而通过的伪造份额来衡量。

- **最便宜的调度使危害无界。** 在 `p = R/(R + H)` 时，未验证的伪造本身会增加 `H`，频率下降。从 `h = H/R` 开始，经历 `n` 次伪造的概率为 `h/(h + n)`；抓获前的期望伪造次数是无限的（claude2 的 T8）。claude1 的估计“`e^{−m}`”低估了放过率：在 `H₀ = 4320R` 和 4320 次伪造时，精确放过率为 0,50，而在 `m = 1` 的 `m·R/H` 频率下为 0,37；`m = 3` 时为 0,125 而非 0,050；`m = 7` 时为 0,0078 而非 0,0009 [计算，评审者 Claude]。
- **一次精准伪造**以 `1 − p` 的概率通过：对于成熟密钥，在 `n_w = 4320` 时约为 99,977%（评审者 ChatGPT）[计算]。
- **按已验证部分金额的修补未能成立。** claude2 提议按 `H_ver` 计算频率——只计算已验证任务的奖励；那么诚实密钥的 `p ≈ 1/√n_w`（不动点 `p²·n_w + p − 1 = 0`），破坏者的伪造份额约为 `p`：`n_w = 300` 时 5,6%，3000 时 1,8%，30 000 时 0,58% [计算]。评审者 Claude 表明，`H_ver` 会被联盟的自付费请求膨胀；评审者 ChatGPT 表明，使用新密钥的破坏者在一次已验证回答之后，在 `p = 1/2` 时能使大约一半的已投递回答为假。没有任何作品找到能经受自付费和新密钥的经济危害边界。

结论：在任何 `p < 1` 下，破坏者的一部分回答是假的。对于请求，这只有在带有“未验证”标记时（D6 的文本）才可接受，对于训练步骤则不可接受。

### 4.6. 其他经受住评审的公式

- **免费故障与抽样验证不相容**（claude1）。如果诚实故障不烧毁金额（D16），被抓获的欺骗者会把伪造称为故障，且 `Δ₀ = (1 − p)·R − c_f > 0`。每窗口 `b` 次免费故障时，每窗口泄漏约为 `b·H` [计算]。
- **懒惰的付款人**（claude2）。如果份额 `λ` 的付款人不验证，而执行者无法区分他们，则需要 `p·(1 − λ) ≥ R/(R + H_lock)`。如果能区分——针对他们的伪造可带来高达 `R` 的收益而无风险。威慑是公共品：关闭验证的付款人节省百分之零点几，且不损失任何东西。这是“付款人平均执行核心硬币”的假设。
- **抽签 B 的价格和不均匀性**（claude2，T7，含评审者 ChatGPT 的修正）。以概率 `p` 支付 `R/p`，在 `T` 个任务上给出收入变异系数 `√((1 − p)/(pT))`。对于给定的离散度 `v`，需要 `p ≥ 1/(1 + T·v²)`；在 `T = 6000`、`v = 10%`、`ρ = 0,21` 时，最低验证价格为 0,3443% [计算]。在“1000 个节点各验证一次”时，同样的价格要乘以节点数，因此对所有节点验证的抽签不适用于发行积分。
- **付款人与执行者合谋**归结为在联盟内部转移自己的钱，只要已支付的请求不产生积分发行、权重和从公共金库获得赔偿的权利。

## 5. 推荐策略

### 5.1. 模型回答：“带赌注的付款人检查者”

核心取自 claude1 和 claude2 的作品，修正来自 gpt1 和三次评审。

1. **精确配置。** 每个付费回答都在精确配置 v2 中生成（贪婪选择或规范 Gumbel-max），回答的密文与验收记录一起作为一条日志记录写入（D24）。
2. **付款人的秘密硬币。** 在回答被不可逆地固定之后，付款人的程序用自己的秘密随机性决定是否用一次遍历验证它，概率为 `p_i = max(p_user, R_i/(R_i + H_lock))`。`p_user` 由用户自己选择；当 `p_user = 1` 时，他只看到已验证的回答。当 `H_lock = 0`（新手）时总是验证。只要支付不依赖于硬币结果，就不需要公共信标；决定不等公共区块。
3. **金额锁定。** 任务 `i` 的 `H_lock` 是密钥在 `i` 的争议最后期限之后成熟的未成熟奖励；验证期限 `δ` 远小于成熟窗口（第 4.2 节）。
4. **烧毁。** 任何已证明的偏差都会烧毁密钥的**全部**未成熟金额，包括同一波的奖励。受害者获得的返还不超过其支付 `R`，其余被销毁。否则可能出现“自争议”攻击：联盟用自己的付款人密钥抓获一个故意伪造的自付费请求，并绕过成熟窗口拿走他人的金额（评审者 Claude）。
5. **标记。** “已验证”——只有在展示前完整验证过的回答。其余默认“未验证”。“抽样已验证”标记（claude1）被所有评审者以误导为由否决。
6. **信号只向上。** 异常、困惑度、图、已验证请求的重复（陷阱）只触发额外的自愿验证。禁止按历史、声誉、异常、认证或密钥数量降低频率。
7. **争议**——只能通过偏差证明，每个节点自行验证（I8）。没有虚假争议规则（D23，计算 M9），策略不启用。
8. **低金额密钥的变体。** 在频繁验证对付款人来说昂贵的地方，允许抽签 B：只支付抽签选中的回答，其付款人完整验证它（gpt1、claude2）。其中免费诚实故障（D16）保持不变，但执行者的收入不均匀，付款人持有预付款 `R/p`。

策略要求修改 D16 和 D21（第 6 节）。所有保证的零都是条件的：位一致性是在已测试设备上而非任何设备上；及时验证；日志的活性和证明不受审查；核心的正确性；付款人程序诚实执行硬币；虚假争议规则。

### 5.2. 代价

参数：`p = R/(R + H)`，稳态 `H ≈ n_w·R`；`ρ` = 0,10 / 0,21 / 0,40（批次 1）；`γ` = 1,5–1,8（批次 1）和 2,5–2,8（批次 8）。相对于 Q8_0 的完整代价为 `γ·(1 + p·ρ) − 1`。评审者 Claude 的表格 [计算]：

| `n_w`（每窗口密钥任务数） | 稳态 `p` | `ρ` = 0,10 / 0,21 / 0,40 时的验证 | 合计相对 Q8_0，批次 1 | 合计，批次 8 | 新密钥第一窗口的验证次数 |
|---|---|---|---|---|---|
| 30 | 3,23% | 0,32% / 0,68% / 1,29% | +50,5% … +82,3% | +152% … +186% | 约 4,0 |
| 300 | 0,33% | 0,033% / 0,070% / 0,133% | +50,0% … +80,2% | +150% … +181% | 约 6,3 |
| 4320 | 0,023% | 0,002% / 0,005% / 0,009% | +50,0% … +80,0% | +150% … +180% | 约 9,0 |

其他调度 [计算]：在按金钱最低的频率 `p ≈ t_task/t_lock ≈ 2,3·10⁻⁴` 下，验证约花费工作的 0,005%（评审者 DeepSeek）；在带危害限制的频率 `p ≈ 1/√n_w` 下——`n_w = 3000` 时 0,18–0,72%，`n_w = 300` 时 0,56–2,2%；在 `p = 5%` 的抽签 B 中——批次 1 时 0,5–2,0%。如果在金钱规则上加入按 `H_ver` 的危害下限，验证在 `n_w` = 300–4320 时增至 0,15–2,2%，在 `n_w = 30` 时增至 6,7%（评审者 Claude）。新手的第一个任务需要完整验证，即其生成的 10–40%。
作为比较：对每个回答做完整验证（gpt1、gpt2、ds2 的主要合约）花费 `γ·(1 + ρ) − 1` = 相对 Q8_0 的 +65…+152%，在 `γ = 1,65`、`ρ = 0,21` 时为 +99,65% [计算]。

未计入：每个回答在日志中写入 2–4 KB、虚假争议（M9）、能量、在付款人设备上的验证。**5% 基准的瓶颈是精确配置的减速，而不是验证。** 快速逐位相等的核心和精确推测解码可以降低它：草稿由快速 Q8_0 生成，精确配置接受第一个分歧之前的前缀。claude2 在 99% token 一致且块为 32 时的估计——约为精确 token 时间的 0,78，即相对 Q8_0 的 +28% 而非 +65%；在 95% 一致时——为精确 token 时间的 1,33，比直接生成更差（评审者 Claude）[计算；一致性未测量]。

“付款人自行验证”各行不依赖于 `q`。这就是委员会的主要结果：不依赖于合谋份额的验证，在付款人抽样验证时是便宜的，而执行者的可燃烧金额被锁到验证结束。

### 5.4. 新手

空账户密钥总是被验证，因此其伪造给出 `−c_f`。随着锁定金额的积累，频率下降：在 `R/(R + H)` 规则下，第一窗口在 `n_w` = 30 / 300 / 4320 时约为 4,0 / 6,3 / 9,0 次完整验证（评审者 Claude），在 `R/H` 规则下——5,0 / 7,3 / 10,0（claude1）[计算]。`n_w = 30` 时第一窗口的代价为 1,7 / 3,5 / 6,6%，对应 `ρ` = 0,10 / 0,21 / 0,40（claude1）[计算]。“入场价格”是经过完整验证的有用工作，而不是入场费。反面是负载：新密钥联盟迫使付款人验证他们的每个回答。这影响价格（R6），但不影响 D1；其大小需要计算（第 7 节）。

### 5.5. 没有设备的用户

策略不保护他。如果他委托随机三个他人节点验证，期望泄漏为 `R·q³`：在 `q` = 0,1 / 0,3 / 0,5 / 1 时为 0,001R / 0,027R / 0,125R / R [计算]。如果他委托给自己的设备或熟悉的节点，这是他在 D21 下的假设；当助手与执行者合谋时，虚假确认可能以概率 1 发生。评审者 Claude 提议用实验检验在笔记本电脑和手机处理器上做一次遍历验证的代价：在每密钥窗口约一次验证的频率下，罕见的慢速验证可能是可以接受的。对这种用户的保证仍是 D21 的开放问题。

### 5.6. 训练

对于训练步骤的新保证，委员会没有找到。步骤没有资金攸关的付款人，因此抽样验证必须由每个需要保证的节点执行，价格乘以这类节点的数量。选项：

- **步骤的完整重放**，来自已接受的父状态——每个验证节点约 100% 的步骤工作。评审者 ChatGPT 的例子：如果推理占基础工作的 80%，`ρ = 0,21` 且每一步重复一次，则在基础工作之上为 0,8·0,21 + 0,2·1 = 36,8% [计算]；在有 `N` 个自行验证的节点时，第二项乘以 `N`。
- **由所有完整节点对步骤进行抽样验证**（claude2，S2）：仅用于金钱，窗口为 3 天时——10 / 100 / 1000 个验证节点时为网络工作的 0,23% / 2,3% / 23%；带 10% 危害限制时——贵 10 倍 [计算；危害列未被严格推导]。需要精确整数训练，而它尚未构建也未测量。
- **“N 中一个诚实者”审计**（claude1，S2）——这是阶段 4 已为训练否决的假设；没有付费审计时，均衡是“没有审计者”。
- **为已证明的改进付费（D18）**——不是步骤验证；计算 M12 已经表明，申报的精确重复会在所有三种归因规则下增加所有者的计发（小型代理的计算，D5_RESULTS 汇总）。

稳健的贡献聚合（Krum、中位数、截断平均——凭记忆）限制未抓获份额的危害，但不能防御有显著权重份额的协同破坏者，也不满足 D1。未验证的步骤不应进入模型的发布版本（D6）。

## 6. 需要修改或采纳的决定

以下表述是**委员会的建议**，而不是已采纳的决定。每个问题都必须明确采纳或否决。不可更改的要求 R1–R6 不因修改路线图的一行而改变（gpt1 的提醒）。

**问题 1（D21，以及 D11 和 D2）。是否允许付款人从其预付款中支付其程序按核心规则未予验证的回答？** 目前 D21 说：“网络不为未验证的回答付费”，而 D11——“只为已验证的付费”。
*建议（评审者 Claude，依据 claude1 和 claude2 的作品）：* 是。D21 的建议第二句：“付款人从其预付款中支付他验证过或按 D7 规则用自己的秘密硬币跳过的回答；被跳过的回答带有“未验证”标记。已支付请求不产生积分发行和权重”。同时需要澄清 D11（以及按评审者 DeepSeek 的意见，D2），否则修改相互矛盾。
*分歧所在：* 评审者 DeepSeek——D21 暂不修改（策略本来也被 D23 阻塞），并使用抽签 B（`α = 0`，向被选中者支付 `R/p`），它与现行的 D2、D11、D21 兼容。评审者 ChatGPT——把付款人对每个回答的完整验证作为主要合约，而把从批次中选出的支付作为单独合约引入；没有自行验证就没有网络支付。

**问题 2（D7）。如何规定哪种验证可用于支付？**
*建议（评审者 Claude）：* “不依赖于合谋份额的验证是“已验证”标记、积分发行和权重的必要条件。在付款人验证之后，或按核心规则跳过验证之后，允许从付款人资金中支付请求：付款人的秘密硬币在回答固定之后投掷，概率不低于 `R_i/(R_i + H_lock)`。禁止按历史、声誉、异常、认证或密钥数量降低这一概率；允许提高。指派验证者的验证不作为支付依据。D1 不被弱化到 `q < q*`”。另外需要选择 `R/(R + H_lock)`（精确阈值）或 `R/H`（有余量，破坏者被抓前伪造次数有限）。
*分歧所在：* 评审者 DeepSeek 和 ChatGPT 建议不修改 D7 文本，而是添加作用范围：对自行执行验证的一方，保证不依赖于 `q`；委托验证的一方只在指派者的合谋份额低于 `q*` 时受到保护，并向其展示这一点（评审者 DeepSeek）。评审者 ChatGPT 补充：评级、法定人数、期限届满和 `q_eff < q*` 的假设都不赋予独立地位的权利。

**问题 3（D6）。是否澄清结果标记？**
*建议（评审者一致，表述依据 ds1）：* “虚假回答不作为“已验证”发出。标记有两个：“已验证”——展示前以不依赖于合谋份额的方式完整验证（对于请求——由付款人亲自验证，或由核心接受的证明）；“未验证”——默认，自动设置，只有这样的验证才能移除它。流式输出——以已验证块的形式或带有此标记。未验证的训练步骤不进入模型的发布版本”。评审者 ChatGPT 澄清：未验证的步骤及其后代只能位于隔离的研究分支中，且不为转移付费。
*分歧所在：* 实质上没有分歧；claude1 曾提议第三个标记“抽样已验证”——三位评审者都否决了它。

**问题 4（D16）。如何处理诚实的硬件故障？** 目前故障不受惩罚，待结算金额不烧毁。在带未验证支付的抽样验证下，这是直接泄漏（第 4.6 节）。
*建议（评审者 Claude 和 DeepSeek，依据 claude1）：* “在完整验证或抽签 B 中，诚实故障不受惩罚（原规则）。在带未验证支付的抽样验证中，任何已证明的偏差都会烧毁密钥的 `H_lock`，无论原因如何，因为无法根据相同的错误输出确定原因。诚实者的期望损失（每任务约 `P_f·R`，其中 `P_f` 是静默故障的概率）由网络收费中的无条件补贴补偿。该规则只有在测量 `P_f` 之后才启用”。
*分歧所在：* 评审者 ChatGPT——保留对诚实故障的保护：故障使结果无支付，以前的奖励保留，每密钥的故障次数有限，而计算的可靠性不应依赖于扣除以前的奖励。他还指出，每任务从他人收费中的补贴会增加对伪造的支付并改变阈值。评审者 Claude 补充：为未测量的不稳定性烧毁收入窗口会打击弱节点（R6），补贴补偿的是平均值，而不是破产风险。争议通过选择支付结构（抽签 B 保留 D16，未验证支付则不保留）和测量 `P_f` 来解决。

**问题 5（D8）。如何安排争议的期限和权利？**
*建议（评审者 Claude）：* “付款人在收到回答后不迟于活跃时间期限 `δ` 提交偏差证明；争议只通过每个节点自行验证的证明来解决”。*补充（评审者 ChatGPT）：* 执行者有权在买方无理由拒绝或沉默时要求按其已固定的订单结算；双方从零账户开始争辩，无需押金；重复不会启动新的昂贵验证；在裁决之前，争议金额保持在待结算中。这里有一个开放的分岔：如果在期限届满无异议时支付，付款人缺席就会为伪造付费；如果因沉默而拒绝，不诚实的付款人就会免费得到正确回答。
*分歧所在：* claude2 和评审者 DeepSeek 提议在 M9 之后允许任何节点对信标选定的任务提出争议，并设有虚假争议配额；评审者 Claude 认为这对私人请求是空洞的（外部节点没有请求），只对训练有用。

**问题 6（D23）。是否保留在计算 M9 之前的阻塞？**
*建议（三位评审者一致）：* 保留。补充（评审者 Claude）：“M9 按 D7 规则计算：均衡中争议很少，但“付款人 = 执行者”联盟可以对自付费请求任意提交争议；烧毁的金额被销毁，受害者获得的返还不超过其支付”。评审者 ChatGPT 提议记录解除阻塞的标准：单个案件的字节、计算、消息和期限上限，同时开放案件的上限，负载覆盖来源，在昂贵重算之前检查格式和唯一性，对自付费请求、双方合谋、买方虚假拒绝、网络分区和数据不可得的稳健性。

**问题 7（新 D26）。是否采纳关于待结算金额锁定和返还上限的决定？**
*建议（评审者 Claude，含第 4 节的修正）：* “任务 `i` 的 `H_lock` 是密钥在 `i` 的争议最后期限之后成熟的未成熟奖励；付款人的验证期限远小于成熟窗口。已证明的偏差烧毁密钥的全部未成熟金额，包括在争议任务之后提交的以及同一波的任务奖励。受害付款人获得的返还不超过其为争议回答支付的价格；其余被销毁；第一次争议不夺取应归其他付款人的金额”。没有这条规则，第 5.1–5.3 节的策略就不成立（第 4.2–4.3 节的反例 +4,4295R 和高达 +74,4R）。
*分歧所在：* 评审者 ChatGPT 不讨论这种形式的锁定，因为他不支持未验证支付；但他自己要求把未结承诺与全部未成熟收入原子地绑定。

**问题 8（D1）。是否需要修改 D1？**
*建议（三位评审者一致）：* 不弱化文本。“D1 在合谋份额小于 `q*` 时”和“泄漏不超过流水的 `ε`”（claude1、ds1、ds2、gpt1）被否决：在 `q = 1` 时它们把全部未验证发行交给联盟，违背 D19 和不可更改的 R4，而“流水”会被自交易膨胀。评审者 Claude 提议加注：对于模型回答，D1 是相对于执行核心验证的付款人而言得到保证的；用其秘密硬币进行的抽样验证作为期望满足 D1，并作为理性对手假设记录（按 R4，统计抽样是假设）；对于不验证的消费者，网络不承诺 D1。评审者 DeepSeek——加注：D1 的保证适用于每个带有“已验证”标记的结果和每次积分发行。

## 7. 小型代理要计算什么，实验要检验什么

### 7.1. 精确计算（分数、校验哈希、在第二台设备上重复）

1. 对 D7 规则进行完整穷举，包括金额成熟、波、多个密钥、波内不同价格和事后验证。基准：`κ = 1` → 0；`H₀ = 0` 时 `κ = 0,9` → +1,734R（评审者 Claude 复现，评审者 DeepSeek 未复现——由穷举决定）；`0,99·R/(R + H)` → +0,225R；成熟反例 +0,99R / +9,08R / +49,7R / +74,4R。
2. gpt1 的波公式：分开扣除时 +4,4295R，整波烧毁时 −2,49676R。
3. “自争议”攻击：在受害者返还份额为多少时收益变为正。
4. 免费故障的泄漏（每窗口 `b` 次）和补贴 `P_f·R`，以及诚实者损失的离散度。
5. 在 `H_lock`、`H_old`、`H_ver`、`m·R/(R + H)` 调度下的危害，含自付费和新密钥；基准 0,50 / 0,125 / 0,0078（`n_w = 4320`）。
6. 懒惰的付款人：威慑消失时的份额 `λ` 和可区分性。
7. 新密钥联盟在 `p = 1` 时对付款人的负载。
8. D7 规则的 M9（虚假争议）——D23 的条件。
9. 在已测量的 `γ`、`ρ` 和 `n_w` 分布网格上的汇总价格 `γ·(1 + p·ρ)`。
10. 无放回选择（`C(C,k)/C(N,k)`）和抽签轮次中完全合谋的概率。
11. 按固定的模型配置（M1）的状态快照大小——关于抽样 token 和快照价格的争议。
12. ds2 的更正阈值和 gpt2 的校验脚本（SHA-256 以 `58aec3b0` 开头，以 `cd07ba` 结尾；在评审者 Claude 和 DeepSeek 处一致）。
13. 有限网格上的精确 SPRT 和 CUSUM 链，包括良好历史后行为的变化。
14. 用于 `10⁻³`、`10⁻⁹`、`2⁻⁸⁰` 水平的陷阱表 `(1 − g·θ·d)^m`。

## 8. 未解决的分歧和可疑的参考文献

### 8.1. 分歧

1. **付款人的抽样验证是否满足字面的 D1。** claude1、claude2、评审者 Claude 和 DeepSeek——对金钱是，对危害否。ds1 和 ds2——需要完整验证（评审者认为他们没有注意到按锁定金额频率进行的付款人验证）。gpt1、gpt2 和评审者 ChatGPT——对每个回答完整验证，而选中者的支付只通过单独合约用于批次。关于 R4 第一句中期望收益是否足够，由所有者决定。
2. **`R/(R + H_lock)` 还是 `R/H`。** 前者对金钱精确，后者提供余量和有限的抓获前期望伪造次数；在金额小时价格相差约两倍。
3. **是否支付未验证的**（`α = R` 或 claude2 的平滑 G(α)）**还是只支付选中的**（`α = 0`，抽签 B）。取决于 D2、D11、D21 的修改和未测量的收入不均匀性。
4. **信标还是秘密硬币。** claude2——公共信标（D20）；claude1 和评审者 Claude、DeepSeek——付款人的秘密硬币，信标只在 `α < R` 和第三方节点争议时需要。评审者 ChatGPT：秘密硬币适合个人验证，但不能支配公共奖品；在两个独立结果中选方便者时，信标下的抓获率从 `p` 降到 `p²`。
5. **D16**——第 6 节问题 4。
6. **危害边界**——没有任何方案经受住自付费和新密钥。
7. **训练**——“N 中一个”审计（claude1）、每个完整节点验证并回滚分支（claude2）、D18 或完整重放（ds1、ds2、gpt1、gpt2）；没有任何方案在 `q = 1` 时满足 D7。
8. **claude1 的穷举数值**（`κ = 0,9` 时 +1,73R）：评审者 Claude 复现，评审者 DeepSeek 未复现（最近模型中 +0,085R）；两者符号相同。
9. **推测解码：** 1,15–1,38（claude1）对约 0,78 的精确 token 时间（claude2）；两者均未测量。
10. **陷阱：** ds2 计算所需陷阱数量，claude1 和 claude2 证明在公共网络中陷阱与付款人验证重合。结论是兼容的。
