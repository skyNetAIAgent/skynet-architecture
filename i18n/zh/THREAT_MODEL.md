## 1. 对手模型

### 1.1. 符号与方案

| 符号 | 含义 |
|---|---|
| `R`, `c` | 任务价格与诚实执行的自身成本，`c ≤ R` |
| `H` | 待结算金额：密钥最近三日内尚未到期的奖励。只能扣除它（没有押金和罚款，要求 R5） |
| `p` | 验证比例：在 A 中 `p = 4R/(R+H)`，但不低于 1%；在 B 中恒定，例如 1% |
| `B` | A 中的扣除：`B = 4R/p − R`，不超过 `H`；当 `p > 1%` 时为 `B = H`，否则 `B = 399R` |
| `k` | 任务的验证者数量，3（抽签轮次平均为 3,5–4,5） |
| `q`, `q_eff` | 合谋群体在模型全部验证者权重中的占比，以及在真正验证该任务的验证者中的占比（第 1.7 节） |
| `G` | 日志中争议的完整价格 |

**方案 A**（当前规范）：抽样验证并从 `H` 中扣除；未被争议的未验证提交会得到支付。**方案 B**（提议）：只支付被抽签选中并得到确认的任务，价格为 `R/p`；未被选中的任务不向任何人支付；被抓住的伪造会烧毁密钥的全部 `H`。B 仅有草图描述，委员会分析的是“按描述所述的 B”：描述中没有新手的路径、验证者按 `H` 的准入、验证者费率以及请求的 `R/p` 来源。

### 1.2. 谁发动攻击

各画像汇总了全部六份作品。组合是必须考虑的：拥有免费密钥的合谋群体、成为合谋群体的租用者、合谋中的长期诚实参与者、与验证者合谋的用户、拥有免费密钥的破坏者。

| 画像 | 拥有什么 | 想要什么 |
|---|---|---|
| 单干者 | 自己的密钥、自己的设备、修改过的程序 | 没有工作或超出工作的积分 |
| 占比为 `q` 的合谋群体 | 共同管理的密钥；结果、计算过程、状态和请求的即时传递；共同资金池 | 让伪造通过、不重算就获得验证报酬、赢下投票 |
| 许多密钥的所有者 | 几乎免费地获得任意多密钥；新密钥的权重和 `H` 为零 | 队列、学徒名额、数据分发、任务指派、B 的票券 |
| 算力租用者 | 按市场价格购买 GPU 小时，工作诚实并由网络支付 | 权重占比，然后是合谋、稀有模型或规则 |
| 不求利益的破坏者 | 准备损失全部尚未到期的奖励 | 损害本身：模型、回答、后门、停机 |
| 空账户参与者 | `H = 0`，没有权重 | 任何无需工作的支付 |
| 长期诚实而后退出者 | 很大的 `H` 和权重；选择时机、规模和波数 | 超过 `H` 加上最后几个任务诚实报酬的收益 |
| 用户 | 自己的请求、积分、争议权、与执行者或验证者的合谋 | 免费回答、为正确回答退款、他人的数据 |
| 中继器、会合点、记录节点、区块链接入点、数据保管者的运营者 | 看到地址和时间，延迟、不转发、展示虚假环境 | 审查、隔离节点、揭露身份、收取记录费 |
| 外部方 | 随机性信标、区块生产者、检查点提供者、受保护模式的生产者、程序分发者 | 移动抽样、塞入虚假历史或程序 |
| 他人设备的所有者 | 被盗或被感染的工作密钥 | 用他人的 `H` 冒险确认伪造 |

### 1.3. 对手能做什么和不能做什么

**能：** 创建任意数量的密钥；运行修改过的程序并读取自己设备上的一切，包括普通模式下的私人请求；在合谋群体内部传递任何数据；关机、选择提交时间、保持沉默、把数据交给某些节点而不交给另一些、只保留唯一副本；租用算力；投票并购买选票；通过智能合约公开提议贿赂（确认保存在日志中，付款可以在无需信任的情况下执行）；作为区块生产者——不发布区块并从两个随机性值中选择一个；控制一部分中继器并包围节点；拥有外部利益或以损害本身为目的。

**不能**（这些是假设，必须明确说明）：伪造他人未被盗密钥的签名、找到哈希碰撞、以两种方式打开承诺、伪造秘密抽签（VRF）；重写公共区块链的最终区块——日志没有管理员密钥且是正确运行的（SPEC 前提 1；程序尚未编写）；在数据包固定之后预测或移动随机性（前提 2；来源尚未选择；混合可防止预测，但不能防止最后一个来源的挑选，N13）；不经计算就得到逐位一致（前提 3；未验证）；改变日志中步骤重算的结果（前提 4；完整模型尚未构建）；更改他人节点的程序（D4）；扣除他人可用积分、为同一编号获得第二次支付、撤回已提交的数据包。

**网络原则上看不到的内容：** 密钥属于谁以及参与者是否独立；节点是否把数据交给了他人；他人计算机上运行着什么；重算与复制他人状态有何区别。如果诚实情况和虚假情况给节点提供相同的数据，任何规则都无法区分它们（[OPEN_QUESTIONS](OPEN_QUESTIONS.md)）。

### 1.4. 对手收益与网络损害

收益按同一初始状态下的整个合谋群体计算，拥有相同的权利、任务以及到最终结算为止的时间范围，包括退出。到期积分、补偿、所获服务和新增权利的价值相加；实际成本（工作、能源、租金、gas、外部支付）相减。合谋群体内部的转账相互抵消，同一积分不重复计算，受害者的损失本身不是合谋群体的收入。收益类型：虚假申报获得的积分（伪造、复制、不重算的确认、他人的行）；相同支付下节省的成本；权重和抽签名额；为正确回答的退款或未支付的数据部分；效应收益——对回答或模型的影响、读取他人请求、控制规则、发行、目录、计划、损害本身。

网络损害单独以其自身单位计算：接受了错误结果；结果在验证前被使用；在没有工作的情况下发行了积分；诚实者损失了 `H`；支付或新手进入被冻结；私人数据被泄露；历史、规则、程序或模型版本被替换；网络把工作花在强加的验证和争议上。没有收益的损害不违反 D1，但可能违反其他要求；表中记为“不适用”并注明所涉及的要求。

### 1.5. D1 的形式化表述

D1（2026 年 11 月 23 日通过）：“骗子得不到想要的东西”；对于任何合谋群体，包括空账户新手和任意数量的密钥，伪造的预期收益相对于诚实工作和相对于不作为都不大于零；有限的正向泄漏不满足该标准。

设 `U(σ)` 为合谋群体在策略 `σ` 下的预期效用。对于每种带有虚假申报的策略，**两个**不等式都必需：

- `Δ₀ = E[U(σ) − U(бездействие)] ≤ 0` —— 每个虚假申报都被替换为拒绝任务
  （此时已赚取的 `H₀` 会到期）；
- `Δч = E[U(σ) − U(честная работа)] ≤ 0` —— 每个虚假申报都被替换为诚实执行。

该要求在任何从 0 到 1 的 `q`、`H = 0` 以及任意数量密钥下都成立。要反驳它，只需一个允许状态和一个正差值。不能与两个基准中较大的那个比较：在不作为为 0、诚实收益为 0,60、虚假申报为 0,20 时，这种比较会得出“没有违反”，尽管 `Δ₀ = +0,20` [计算]。

一份作品建议将 D1 分为经济层面（仅积分）和效应层面（对回答和模型的影响、读取请求、损害）。委员会不自行采纳：该问题已提交所有者（第 5 节，问题 1）。表中仅有效应收益的情况标为“否（效应）”。

### 1.6. “拒绝依据的数据”一列的一般原则

当执行者与所有被指派的验证者合谋时，节点只能看到一致的数据：结果与过程的指纹、带包含证明的已揭示状态。所有这些都与伪造相容。独立可验证的只剩下输入和固定的模型，节点可以据此自行重算任务——约增加 +100% 的工作 [计算]；A 和 B 都不要求这样做，而对于私人请求，外部节点连输入都没有。因此表中经常写“否，除非完整重算”。

### 1.7. 合谋占比 `q_eff`

所有“高达 91%”之类的阈值，都指合谋群体在真正验证该任务的人当中的占比。
`q_eff` 是验证者中满足以下条件的合谋群体占比：(1) 被允许参与该任务（按 SPEC 规则 2.6，
对于长期执行者的任务需要 `H_v ≥ B`，最高为 `399R`），(2) 在轮次期限内回答，以及 (3) 获得了
验证所需的数据。示例 [计算]：3000 台诚实的家用设备各运行 8 小时，以及 100 台诚实的
全天候设备，对抗 800 台租用的全天候设备。对手在全部权重中的占比为 42,1%
（每日 45 600 设备小时中的 19 200）；家用设备大约积累 `144R < 399R`
且不能参与长期执行者的任务；在被允许者中 `q_eff = 800/900 = 88,9%`，
`q_eff³ ≈ 0,70`。评审者的保留意见：这仅涉及 `B = 399R` 的任务。条件 (3) 可以在任意总占比下
将 `q_eff` 提高到 1（N2）。公式 `q^k` 仅对独立选择成立；
在 SPEC 中轮次持续到收到三个回答，对于部分合谋需要回答者的分布。

### 1.8. 基本公式 [计算]

- **A，一次伪造：** 收益 `R − 4R(1 − q³)`；当 `q < 0,9086` 时亏损。**A 的新手：**
  `p = 1`，`B = H = 3R`，收益 `R(4q³ − 3)`。
- **A，带伪造退出**（FIRST_RUN 在单台设备上的穷举，未确认）：从
  `q = 0,875` 起有利可图（任意规模、三波、“进行中的工作不超过 `H` 的三分之一”规则；0,875 时为 1,00004·H₀，
  0,880 时为 1,034·H₀），从 0,890 起（相同任务），无三分之一规则时从 0,800 起；在没有合谋的
  9200 万种策略中不存在有利可图的退出（最佳为 0,980·H₀）。这是对策略族的穷举，不是证明。
- **B，一次伪造**在 `q^k > pH/(R + pH)` 时有利；当 `p = 1%`、`k = 3` 时：`H = 400R` 对应
  `q ≈ 0,928`，`40R` 对应 `0,659`，`H = 0` 时任意 `q > 0`。每次伪造的平均毛支付为
  `R·q^k`，与 `p` 无关。
- **B，`N` 次伪造的一波：** `E = a^N·H₀ + N·a^(N−1)·q^k·R`，`a = 1 − p(1 − q^k)`。当 `H₀` 低于 2,8R / 14,3R / 52R / 105R / 269R（对应 `q` = 0,3 / 0,5 / 0,7 /
  0,8 / 0,9）时，第一次伪造有利。当 `H₀ = 0` 时，每个密钥的最大收益约为 `q^k·R/(e·p·(1 − q^k))`：`q` = 0,1 / 0,3 / 0,5 / 0,7 对应
  0,037R / 1,0R / 5,3R / 19R。未穷举的单波是下界。
- **虚假支付的概率**（无外部争议的任务）：A 中为 `1 − p + p·s`，B 中为 `p·s`
  （`s` 为抽中时完全合谋的概率）；当 `p = 0,01`、`s = 0,125` 时为 0,99125 和 0,00125，
  而 `R = 1` 时的虚假毛支付为 0,99125 和 0,125。不能只按虚假支付频率比较方案。

## 2. “60 与 59”核对

在 SPEC 中正好有 60 行（12 + 12 + 10 + 5 + 11 + 6 + 4）：18 项已封堵、6 项亏损、19 项受限、
16 项开放，以及**一项“非攻击”——第 1.9 行**（提交在他人设备上计算出的正确结果，D2 决定允许这样做）；CURRENT_DESIGN 第 9 节的汇总和 SPEC 中的“简要”段落只合并了四个类别，丢失了第五个，因此为 59。全部六份作品和全部三位评审者独立得出了这一结论。正确写法：60 = 18 + 6 + 19 + 16 + 1。

## 3. 攻击表

### 3.1. 符号说明

**状态：** 已封堵——节点在所述前提下根据日志数据拒绝攻击；
亏损——攻击可行，但平均而言在所述边界以内是亏损的；受限——可行，但损害或
收益受规则限制；开放——没有解决方案；非攻击。

**D1：** 是——对任何合谋群体收益不大于零；**否**——存在至少相对于一个
基准具有正收益的策略；有条件——仅在所述不依赖于合谋占比的前提下成立
（SPEC 前提 1–4，尚未构建）；否（效应）——没有金钱收益或未确定，但达到了效应收益
（第 1.5 节）；不适用——攻击中没有为获利而进行的虚假申报，涉及所述要求；
?——规则未规定，收益符号未确定。

**数据**——在执行者与所有验证者合谋时，节点依据哪些独立可验证的数据拒绝虚假申报。“有争议”——作品或评审者存在分歧，争议未解决。

**A 与 B 的比较。** 按所述形式的 B 在空和低 `H`、`0 < q < 0,909` 时比 A 差：
空密钥每次尝试无损失地获得 `R·q^k`（N16）。当 `q = 0` 时 B 更好：未被选中的

（`q^k R − (1 − q^k)·3R`，与 A 中相同 [计算]），但 B 失去恒定的低验证比例。
这是阶段 2 中 D3 决定的输入，而非决定本身。

### 4.3. 共同根源

在两个方案中，结果的常规验收都依赖于参与者随机样本的一致，
也就是依赖于在合谋时什么也证明不了的签名。因此保护边界总是
以合谋占比 `q_eff` 表示，而 `q_eff` 可以通过租用算力、夺取稀有
模型、按 `H` 的准入规则（N5）、数据饥饿（N2）、被盗密钥（N9）或
长期停机（N6）来提高。完全合谋时独立可验证的数据只有输入和模型，
节点可以据此自行重算任务；A 和 B 都不要求这样做，而对于私人
请求，节点连输入都没有。D1 只有通过不依赖于合谋占比的验证
（阶段 4 [ROADMAP](ROADMAP.md)）才能实现，或者由所有者决定将 D1 明确弱化为“在 `q < q*` 时”。

### 4.5. 被反驳的结论

这些第一轮作品中的陈述被评审者认定为错误；它们未被移入表中。

| 陈述 | 出处 | 为何错误 |
|---|---|---|

## 5. 给所有者的问题

没有这些决定，阶段 1 无法结束。委员会不采纳它们。全部十二个问题已于 2026 年 11 月 24 日根据所有者的授权解决（[ROADMAP](ROADMAP.md) 第 3 节中的决定 D6–D17）。

1. **效应是否纳入 D1？** *(已决定——D6：是。)* 一份作品建议区分经济 D1（仅积分）
   和效应 D1（对回答和模型的影响、读取请求、损害本身）。“骗子
   得不到想要的东西”按字面含义包括效应；那么验证前使用结果
   （N21）在两个方案中、对任意 `q` 都违反 D1，只能通过
   在交付和推进前验证来封堵（代价——延迟和内存）。
2. **要求不依赖于合谋占比的验证，还是将 D1 弱化为“在 `q < q*` 时”？** *(已决定——D7：要求不依赖于合谋占比的验证。)*
   没有两者之一，D1 在 A 和 B 中都无法实现。
3. **交换时一个部分的泄漏** *(已决定——D10：违反 D1；只交换一条日志记录。)*（4.1、5.6）：没有可信方的诚实交换在一般
   情况下不可能。应将其明确承认为假设，还是视为违反 D1？
4. **零账户争议** *(已决定——D8：仅限被指派的验证者和就自身请求提出争议的用户。)*（N23）：ROADMAP 要求它，SPEC 不要求。那么在没有押金的情况下，
   用什么来限制虚假争议的流量？
5. **不可变更核心的组成** *(已决定——D11：验证、对已验证内容的支付、发行、争议和日志规则；其余属于可变更部分。)*（3.7）：发行规则、质押、网络费、
   制动和目录是否属于其中，还是只有验证？
6. **训练计划的批准规则** *(已决定——D9：计划由规则根据目录和考试推导得出。)*（1.7，ROADMAP“尚未解决的问题”，第 5 点）：谁以及如何
   允许任务发行积分。
7. **权重和窗口的时间** *(已决定——D12：网络活跃时间。)*（N6）：日历时间还是网络活跃时间。
8. **B 中的任务准入** *(已决定——D13：是，采用方案 A 的新手路径。)*（N16）：是否在 B 中引入访问对 `H` 的依赖，同时明白届时
   B 会失去恒定的低验证比例。这是 D3 的输入。
9. **争议成本** *(已决定——D14：最便宜的二层网络；差额由网络费支付。)*（N3）：为估算 `G` 考虑哪条链，以及谁承担差额 `G − B`——
   有理的一方还是网络。
10. **是否为重复验证和学徒复检支付** *(已决定——D15：可以被复制的简单重算不予支付。)*（2.2、N1），如果复制无法
    与重算区分？
11. **诚实的硬件故障：** *(已决定——D16：否；任务不予支付，待结算金额不会烧毁。)* 是否按欺骗同样的方式扣除。
12. **B 中请求的 `R/p` 支付来源** *(已决定——D17：仅来自用户支付。)*（4.3）：仅来自用户支付，还是也来自发行。
