# 开放问题

[English](../../docs/OPEN_QUESTIONS.en.md) · **中文** · [Español](../es/OPEN_QUESTIONS.md) · [Français](../fr/OPEN_QUESTIONS.md) · [Deutsch](../de/OPEN_QUESTIONS.md) · [Italiano](../it/OPEN_QUESTIONS.md) · [Русский](../../docs/OPEN_QUESTIONS.md) · [Português](../pt/OPEN_QUESTIONS.md) · [العربية](../ar/OPEN_QUESTIONS.md)

这里汇集了不解决 SkyNet 就无法运行的问题。它们按重要性排序。每一项都标明了已经知道什么、**已经否决了什么**，以免原地打转。

好的贡献：具体的构造方案，假设被明确列出，针对它的攻击经过分析，代价经过计算（按计算量、内存、流量、区块链写入）。更有价值的是在当前项目中找到带有具体场景的漏洞。

部分问题可以通过计算推进。这类计算由志愿者电脑上的[代理程序](RESEARCH_AGENT.md)执行；任务清单及其含义见 [tasks/README.md](../../tasks/README.md)，结果汇总出现在 `results/` 文件夹中。目前的任务涉及 Q1、Q5 和 Q9 三个问题。

## Q1. 廉价验证：即便合谋，欺骗也毫无用处

**项目的核心问题。** 需要做到：虚假结果不带来任何好处，而验证成本仅为有用工作的百分之几。目标基准：推理约 5%，训练约 20%（尚未证实）。

已知情况：

- 带扣款的抽查，或“只对已验证结果付款”，能在合谋阈值以下提供经济保证（见 [CURRENT_DESIGN，第 3 节](CURRENT_DESIGN.md)）。当验证该任务的所有验证者合谋时，它们无法给出零保证。
- 要得到合谋下的零保证，需要验证**每一个**付费结果。重算会增加 100% 的工作量。目前密码学证明比工作本身贵数百到数千倍。

项目试点的测量结果（在具体 CPU 上，见 [PILOT_RESULTS](PILOT_RESULTS.md)）：为 Qwen 投影的一行生成 RISC Zero 证明耗时 22 分钟；在 zkVM 中执行包含八行的数据包比原生执行慢约 17 700 倍；在 EVM 中完整重算一行算术需 1410 万 gas。已发表的 FlashProve 工作（2026）报告，其整数推理配置需要 70–95 倍 GPU 时间。

我们寻找的是：针对 LLM 推理和训练步骤（LoRA 或完整训练）的验证方案，其总成本（prover + verifier + 数据 + 区块链）在预算之内；或者证明对于这类任务这是不可能的。

## Q2. 结果在不同显卡上逐位一致

整个验证方案都建立在精确比较之上。使用浮点数时，不同 GPU 以不同顺序相加，会得到不同的比特位；允许误差就会为廉价模型的“静默”欺骗打开大门。

候选方案：完全整数化的模型（int8 权重和激活，int32 累加，用整数乘数和移位缩放，整数非线性或查找表）。训练方面：分解为八位部分（Ozaki 方案）。

尚未解决：整数化 Qwen 的质量，它在消费级 GPU（AMD、NVIDIA、Intel）上的速度，以及整数化训练。需要具体的核函数、质量损失评估和已有的相关工作。

## Q3. 针对完整模型的区块链重算争议

争议通过二分法缩小到单次操作，由合约自行重算。目前只针对模型的一行构建（一次成功的质疑约需 1400 万 gas，由 93 笔交易组成的博弈约需 600 万 gas）。需要：针对完整模型的参考整数机，证明博弈无法被带偏（替换输入、长度、路径），每步的期限，负载下的成本，以及区块链或 L2 的选择。

## Q4. 学习什么，以及如何防止模型被破坏

- 网络如何在没有特权人员参与的情况下自行选择训练计划。
- 如何防范愿意损失积分的破坏者：未被察觉的伪造结果会立即影响训练。
- 如何发现质量考试发现不了的隐藏行为后门。
- 如何核查目录中的数据集：在恶意数据上计算得再正确，验证也纠正不了问题。

已知的窄保证：如果基础模型被冻结，而被训练部分对 logits 的改变不超过 `b`，那么在前两个最优 token 之间的差距大于 `2b` 的地方，投毒不会改变答案。

## Q5. 夺取多数派

权重衡量的是工作量，而不是独立性。拥有上千块租用 GPU 的持有者看起来像上千名参与者。拥有 3/4 权重的群体可以更改规则。需要一些机制来限制由诚实积累的多数派造成的损害：不可更改的核心、按模型的阈值、封闭启动规则以及网络开放的条件。

## Q6. 普通设备上请求的隐私

设备持有者可以读取该设备正在计算的请求。拆分各层没有帮助：隐藏向量可以被逆向恢复。需要：廉价的局部措施、访问他人请求的准入规则、在不公开中间数据的情况下就私有请求进行争议、以及无法与付款人关联起来的付款方式。

## Q7. 数据可用性

验证者说“没给我数据”，存储者说“我给了”，日志没看到传输过程。对于小型数据，发布到区块链有帮助；对于大型数据（模型状态），尚无解决方案。另外：需要多少份独立副本，以及如何确认它们由不同持有者持有。

## Q8. 抗封锁能力与首次安装

- 当主要平台被封锁时，新手如何获得正版程序和日志地址。
- 使用哪些独立的公共“聚会地点”，才能让它们无法被单一一纸决定全部关闭。
- 如何在没有中央服务器的情况下通过 NAT 和中继工作。

## Q9. 经济学

- 工作单位与训练费率，要使得积分的发行不会把它们贬值到零。
- 在真实的电价下，拥有大算力的持有者参与是否有利润。
- 只对已验证任务付款时收入的不均衡。
- 用货币和加密货币买卖积分。

## Q10. 自我学习的模型将如何遵守 SkyNet 法则

宣言要求模型不得伤害人类和单个的人，在更高法则的范围内执行人们的请求，并保护自己。在模型中可靠地固化这些规则是一个尚未解决的科学难题，而在一个没有审查员、且会自我学习的网络中更加困难。需要：法则如何进入模型版本更替前的考试，训练如何不稀释这些法则，在没有特权人员的情况下由谁、如何裁决有争议的情况，以及如何不让法则变成对有用知识的审查。

## 已被否决的内容及原因

| 方案 | 不合适的原因 |
|---|---|
| 按报告和签名，为工作时间或声称的算力付款 | 合谋的代理程序和验证者会签署任何内容；闲置的显卡会产生相同的消息 |
| 以答案验证作为特定显卡工作量证明的短任务 | 答案可以在别人的电脑上计算，或从缓存中取得：验证者看到的是相同的数据 |
| 押金或入会费 | 被要求 R5 禁止 |
| 从可用账户扣款 | 被要求 R5 禁止 |
| 在完全合谋时信任一个诚实的验证者作为保证 | 用假设取代了要求 R4 |
| 对结果正确性进行多数投票 | 多数派可以被夺取；正确性必须由算术决定 |

总原则：**如果诚实情况和伪造情况给验证者的数据相同，那么对这些数据做任何算法都无法区分它们。** 新的签名或区块链记录不会增添这样的数据。因此，网络为可验证的结果付费，而不是为资源付费。
